# EX-025-001 - Distribution d'experts

## Énoncé

Simulez la distribution de `N` experts sur `D` devices. Pour chaque token, assignez un expert et calculez la charge par device.

## Ce que l'exercice vérifie

L'exercice vérifie que le routage MoE devient rapidement un problème matériel. Un bon routage côté modèle peut produire une mauvaise charge côté devices.

## Solution détaillée

Prenons :

```text
N = 8 experts
D = 4 devices
```

Placement simple :

```text
device 0 : experts 0, 1
device 1 : experts 2, 3
device 2 : experts 4, 5
device 3 : experts 6, 7
```

Supposons les assignations de tokens :

```text
[0, 0, 1, 2, 2, 2, 4, 7, 7, 7, 7]
```

Charge par expert :

```text
expert 0 : 2
expert 1 : 1
expert 2 : 3
expert 3 : 0
expert 4 : 1
expert 5 : 0
expert 6 : 0
expert 7 : 4
```

Charge par device :

```text
device 0 : expert 0 + 1 = 3
device 1 : expert 2 + 3 = 3
device 2 : expert 4 + 5 = 1
device 3 : expert 6 + 7 = 4
```

Le device le plus chargé est `device 3`.

Le déséquilibre est visible même avec un petit exemple. Si ces tokens représentent un gros batch ou un flux production, le device 3 peut devenir le goulot.

## Points importants

- Il faut distinguer charge par expert et charge par device.
- Le placement des experts influence le coût.
- Un expert populaire peut saturer son device.
- Un histogramme suffit souvent à révéler le problème.
- Le load balancing doit tenir compte du matériel.

## Prolongement

Une simulation utile devrait aussi compter la communication : combien de tokens doivent quitter leur device d'origine pour rejoindre l'expert choisi ?
