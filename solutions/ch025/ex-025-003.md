# EX-025-003 - Hotspot matériel

## Énoncé

Expliquez comment un routeur apparemment bon côté modèle peut créer un hotspot matériel.

## Ce que l'exercice vérifie

L'exercice vérifie la séparation entre qualité du routage et santé de l'infrastructure.

## Solution détaillée

Un routeur peut envoyer beaucoup de tokens vers le même expert parce que cet expert améliore la loss. Côté modèle, cela semble rationnel.

Mais si cet expert est placé sur un device précis, ce device reçoit une charge disproportionnée.

Conséquences :

- file d'attente locale ;
- mémoire saturée ;
- latence plus élevée ;
- communication accrue ;
- débit global réduit ;
- tokens débordés si capacité limitée.

Le problème est classique en systèmes distribués : une décision localement bonne crée un hot spot global.

Exemple :

```text
expert 3 reçoit 45 % des tokens
expert 3 est sur GPU 1
GPU 1 devient le goulot
```

Pendant ce temps, d'autres GPUs peuvent être sous-utilisés.

Le routeur doit donc être évalué avec des métriques modèle et système :

- qualité ;
- charge par expert ;
- charge par device ;
- latence par device ;
- communication ;
- taux de débordement.

## Points importants

- Un routage utile pour la loss peut déséquilibrer le matériel.
- Le placement des experts compte.
- Le hot spot augmente latence et réduit débit.
- Le monitoring doit inclure les devices.
- Le load balancing doit intégrer la réalité système.

## Prolongement

Une mitigation possible est un routage limité par device ou une pénalité qui tient compte de la charge matérielle, pas seulement de l'expert abstrait.
