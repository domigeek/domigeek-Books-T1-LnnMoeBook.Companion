# EX-037-003 - Choisir une stratégie selon le goulot

## Énoncé

Pour cinq scénarios différents, choisissez data parallel, model parallel, pipeline parallel, expert parallelism ou une combinaison. Justifiez le choix.

## Ce que l'exercice vérifie

L'exercice vérifie que le parallélisme est une réponse à un goulot précis. Il ne faut pas choisir une stratégie parce qu'elle paraît moderne, mais parce qu'elle attaque la contrainte dominante.

## Solution détaillée

Voici cinq scénarios et les choix associés.

### Scénario 1 - Beaucoup de données, modèle qui tient sur un GPU

Choix : `data parallel`.

Le modèle complet tient sur chaque appareil. Le problème principal est de traiter plus d'exemples par unité de temps. On duplique donc le modèle sur plusieurs GPU, chaque GPU traite un mini-batch différent, puis les gradients sont synchronisés.

Avantage :

- simple à comprendre ;
- très bon premier levier ;
- compatible avec beaucoup de modèles.

Limite :

- coût de synchronisation des gradients ;
- efficacité réduite si les batchs deviennent trop grands ;
- ne règle pas le problème d'un modèle trop gros.

### Scénario 2 - Modèle trop grand pour la mémoire d'un seul GPU

Choix : `model parallel` ou `tensor parallel`.

Ici, le problème n'est pas le débit des données. Le modèle lui-même ne tient pas sur un appareil. Il faut découper certaines parties du modèle entre plusieurs appareils.

Avantage :

- permet d'exécuter un modèle impossible à charger autrement ;
- utile pour grosses matrices et grands blocs.

Limite :

- communication fréquente entre partitions ;
- complexité plus élevée ;
- sensibilité au placement des couches ou tenseurs.

### Scénario 3 - Réseau très profond avec étapes séquentielles lourdes

Choix : `pipeline parallel`.

Le modèle peut être divisé en segments successifs. Chaque appareil exécute une partie de la chaîne. Les micro-batchs circulent dans le pipeline.

Avantage :

- permet de répartir un réseau profond ;
- exploite plusieurs appareils même si les couches sont naturellement séquentielles.

Limite :

- bulles de pipeline ;
- latence plus complexe ;
- équilibrage difficile si les segments n'ont pas le même coût.

### Scénario 4 - MoE avec beaucoup d'experts, peu d'experts actifs par token

Choix : `expert parallelism`.

Le problème principal est le nombre total d'experts. On place différents experts sur différents appareils. Le routeur envoie les tokens vers les experts actifs.

Avantage :

- augmente la capacité totale sans activer tout le modèle à chaque token ;
- correspond directement à l'architecture MoE ;
- permet la spécialisation des experts.

Limite :

- dispatch de tokens coûteux ;
- risque de déséquilibre de charge ;
- experts chauds et experts morts ;
- communication inter-appareils.

### Scénario 5 - Très grand modèle MoE entraîné sur beaucoup de données

Choix : combinaison.

Un système réel combine souvent plusieurs stratégies :

```text
data parallel
  pour répliquer des groupes complets

model/tensor parallel
  pour les blocs trop gros

expert parallelism
  pour distribuer les experts

pipeline parallel
  si la profondeur impose un découpage par étapes
```

La combinaison est justifiée seulement si chaque niveau répond à une contrainte mesurée. Sinon, on ajoute de la coordination sans bénéfice clair.

## Règle pratique

| Goulot dominant | Stratégie naturelle |
|---|---|
| trop de données, modèle raisonnable | data parallel |
| modèle trop gros en mémoire | model/tensor parallel |
| profondeur séquentielle lourde | pipeline parallel |
| nombreux experts spécialisés | expert parallelism |
| plusieurs goulots simultanés | hybride |

## Points importants

Distribuer ne supprime pas le travail. Distribuer déplace le travail, ajoute de la communication et demande de la coordination. La bonne stratégie est celle qui réduit le goulot dominant plus qu'elle n'ajoute de surcharge.

## Prolongement

Avant de choisir une stratégie, il faut mesurer : mémoire utilisée, temps forward, temps backward, temps réseau, utilisation GPU, taille du modèle, taille de batch et distribution de charge. Sans ces mesures, le choix relève davantage de l'habitude que de l'architecture.
