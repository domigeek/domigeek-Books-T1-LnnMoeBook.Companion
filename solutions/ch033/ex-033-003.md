# EX-033-003 - Budget agentique

## Énoncé

Proposez des budgets pour un agent de correction de code : nombre d'étapes, appels d'outils, durée, coût et tentatives de test.

## Ce que l'exercice vérifie

L'exercice vérifie qu'un agent doit avoir des limites opérationnelles. Sans budget, il peut tourner en boucle ou coûter trop cher.

## Solution détaillée

Budgets proposés :

| Ressource | Budget |
|---|---:|
| Étapes de raisonnement/action | 12 |
| Lectures de fichiers | 30 |
| Éditions de fichiers | 6 |
| Commandes de test | 4 |
| Durée totale | 20 minutes |
| Coût modèle | seuil défini par projet |
| Tentatives sur même erreur | 2 |

Règles d'arrêt :

- tests passent ;
- erreur identique après deux tentatives ;
- fichier critique non compris ;
- changement demandé dépasse le périmètre ;
- outil nécessaire non disponible ;
- risque sécurité détecté.

Fallback :

```text
produire diagnostic + patch partiel + questions précises
```

Le budget doit être adapté au risque. Corriger une faute de typage ne mérite pas le même budget qu'une réécriture multi-module.

## Points importants

- Les agents doivent avoir des limites.
- Les tentatives répétées doivent être bornées.
- Les tests font partie du budget.
- Le fallback doit être prévu.
- Le budget protège coût, temps et sécurité.

## Prolongement

Un agent sérieux ressemble moins à un assistant libre qu'à un processus d'ingénierie avec permissions, journaux et critères d'arrêt.
