# EX-033-004 - Lire MCP avec prudence

## Énoncé

Expliquez pourquoi un protocole comme MCP peut améliorer l'intégration des outils sans garantir la sécurité du système.

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre interface standardisée et sécurité complète.

## Solution détaillée

Un protocole comme MCP peut améliorer l'intégration parce qu'il standardise la façon dont un modèle ou un agent découvre et appelle des outils.

Avantages :

- contrats plus clairs ;
- intégration plus modulaire ;
- séparation entre modèle et outils ;
- découverte de capacités ;
- logs plus structurables.

Mais un protocole ne garantit pas à lui seul :

- que l'outil est sûr ;
- que l'utilisateur a consenti ;
- que les permissions sont correctes ;
- que le sandbox est suffisant ;
- que les données sensibles sont protégées ;
- que les actions destructives sont confirmées ;
- que les logs sont audités.

La sécurité vient des politiques autour du protocole :

```text
authentification
autorisation
sandbox
validation des entrées
confirmation humaine
limites de coût
audit
révocation
```

## Points importants

- MCP peut standardiser l'accès aux outils.
- Standardiser n'est pas sécuriser complètement.
- Les permissions restent indispensables.
- Les actions dangereuses doivent être contrôlées.
- L'audit doit être conçu explicitement.

## Prolongement

Un bon protocole réduit le chaos d'intégration. Il ne remplace pas l'architecture de sécurité.
