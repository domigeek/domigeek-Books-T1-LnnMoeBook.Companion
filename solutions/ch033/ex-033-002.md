# EX-033-002 - Contrat d'outil

## Énoncé

Définissez le contrat complet d'un outil `search_docs` utilisé par un agent documentaire.

## Ce que l'exercice vérifie

L'exercice vérifie qu'un outil agentique doit être un contrat contrôlé, pas une fonction libre sans garde-fous.

## Solution détaillée

Contrat :

```json
{
  "name": "search_docs",
  "description": "Recherche des documents autorisés dans un corpus versionné.",
  "input": {
    "query": "string",
    "topK": "integer",
    "filters": {
      "projectId": "string",
      "dateMin": "string",
      "documentType": "string"
    }
  },
  "output": {
    "results": [
      {
        "documentId": "string",
        "chunkId": "string",
        "score": "number",
        "title": "string",
        "excerpt": "string",
        "sourceDate": "string",
        "permissions": ["string"]
      }
    ]
  }
}
```

Erreurs :

- `Unauthorized`;
- `CorpusUnavailable`;
- `InvalidQuery`;
- `RateLimited`;
- `NoReliableSource`.

Permissions :

- vérifier l'utilisateur avant la recherche ;
- filtrer les documents non autorisés ;
- journaliser les accès.

Métriques :

- latence ;
- nombre de résultats ;
- score minimal ;
- version d'index ;
- coût ;
- taux d'échec.

Politique de validation :

```text
ne pas répondre si aucune source au-dessus du seuil
indiquer les sources utilisées
refuser les documents non autorisés
```

## Points importants

- Un outil doit avoir schéma d'entrée et sortie.
- Les permissions sont dans le contrat.
- Les erreurs doivent être explicites.
- Le coût et la latence doivent être observables.
- La version de corpus doit être journalisée.

## Prolongement

Un agent qui utilise des outils sans contrats solides est difficile à sécuriser. Le contrat est la frontière entre raisonnement et action.
