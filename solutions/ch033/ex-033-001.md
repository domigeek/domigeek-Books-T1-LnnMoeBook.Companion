# EX-033-001 - Pipeline, workflow ou agent

## Énoncé

Pour chacun des cas suivants, choisissez pipeline, workflow ou agent : résumer un document, traiter une réclamation client avec approbation, diagnostiquer un bug intermittent, extraire des champs d'une facture, corriger du code avec tests.

## Ce que l'exercice vérifie

L'exercice vérifie le choix du bon niveau d'autonomie. Tout ne mérite pas un agent.

## Solution détaillée

| Cas | Choix | Justification |
|---|---|---|
| Résumer un document | Pipeline | étapes stables : lire, résumer, vérifier longueur |
| Réclamation avec approbation | Workflow | étapes connues, décision humaine ou règle de validation |
| Bug intermittent | Agent | exploration, hypothèses, outils, tests, adaptation |
| Extraire champs d'une facture | Pipeline | tâche structurée avec schéma de sortie |
| Corriger du code avec tests | Agent contrôlé | nécessite inspection, édition, test, retry |

Un pipeline convient quand les étapes sont fixes.

Un workflow convient quand il y a des branches, validations ou approbations, mais un processus bien défini.

Un agent devient utile quand le système doit choisir ses prochaines actions selon les résultats observés.

Le risque agentique est le coût et la dérive. Il faut donc imposer :

- budget d'étapes ;
- permissions ;
- outils autorisés ;
- conditions d'arrêt ;
- logs ;
- fallback humain.

## Points importants

- Pipeline : étapes fixes.
- Workflow : étapes contrôlées avec branches.
- Agent : exploration conditionnelle.
- L'autonomie coûte cher.
- Les agents doivent avoir des limites.

## Prolongement

La bonne architecture est souvent moins agentique qu'on l'imagine. Un pipeline fiable vaut mieux qu'un agent théâtral pour une tâche stable.
