# EX-011-003 - Contexte ou mémoire

## Énoncé

Classez les éléments suivants comme contexte temporaire, mémoire persistante ou outil externe : historique de conversation, base documentaire vectorisée, résultat d'appel API, profil utilisateur versionné, instruction système.

## Ce que l'exercice vérifie

L'exercice vérifie une distinction d'architecture. Dans un système à base de modèle, tout ce qui influence la réponse n'est pas de la mémoire au même sens.

Confondre contexte, mémoire et outil rend le système difficile à auditer.

## Solution détaillée

Voici une classification possible.

| Élément | Classification principale | Commentaire |
|---|---|---|
| Historique de conversation | Contexte temporaire | Il est injecté dans la fenêtre courante. Il influence la réponse, mais n'est pas forcément persistant. |
| Base documentaire vectorisée | Mémoire externe persistante | Elle stocke des documents récupérables, souvent avec métadonnées et versionnement. |
| Résultat d'appel API | Observation ou sortie d'outil externe | Le résultat peut être ajouté au contexte, mais sa source est un outil. |
| Profil utilisateur versionné | Mémoire persistante gouvernée | Il doit être versionné, corrigible, auditable et soumis à permissions. |
| Instruction système | Contrainte de contexte | Elle cadre le comportement du modèle dans la session ou l'appel. |

Certains cas sont ambigus.

Un historique de conversation peut devenir mémoire persistante si le système le résume, le sauvegarde et le réutilise plus tard. Mais tant qu'il est seulement placé dans le prompt courant, il reste du contexte temporaire.

Un résultat d'API peut être stocké ensuite dans une mémoire persistante, mais ce n'est pas sa nature initiale. Initialement, c'est une observation obtenue par outil.

Une instruction système n'est pas une mémoire utilisateur. C'est une contrainte opérationnelle. La mélanger avec une mémoire personnelle serait dangereux, parce qu'elle n'a pas le même statut ni les mêmes règles de modification.

## Points importants

- Le contexte temporaire influence l'appel courant.
- La mémoire persistante survit aux appels et doit être gouvernée.
- Un outil externe produit une observation ou une action.
- Une instruction système est une contrainte, pas une connaissance utilisateur.
- Les cas ambigus doivent être explicités dans le contrat d'architecture.

## Prolongement

Une architecture propre devrait annoter chaque information avec :

```text
source
durée de vie
permission
version
date
niveau de confiance
mode de suppression
```

Ce n'est pas de la paperasse. C'est ce qui évite qu'un système mélange un fait, une préférence, une instruction et un vieux résultat d'outil.
