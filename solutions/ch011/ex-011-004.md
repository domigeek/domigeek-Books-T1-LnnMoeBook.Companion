# EX-011-004 - Coût de l'attention

## Énoncé

Comparez le nombre de relations token-token pour des séquences de longueur `1 000`, `2 000` et `8 000` dans une attention standard.

## Ce que l'exercice vérifie

L'exercice vérifie la croissance quadratique de l'attention dense. Dans une attention standard, chaque token peut regarder chaque autre token.

Le nombre de relations est donc approximativement :

```text
n * n = n^2
```

## Solution détaillée

Pour une séquence de longueur `1 000` :

```text
1 000^2 = 1 000 000
```

Il y a un million de relations token-token.

Pour une séquence de longueur `2 000` :

```text
2 000^2 = 4 000 000
```

La longueur est multipliée par `2`, mais le nombre de relations est multiplié par `4`.

Pour une séquence de longueur `8 000` :

```text
8 000^2 = 64 000 000
```

On arrive à soixante-quatre millions de relations.

Tableau résumé :

| Longueur `n` | Relations `n^2` |
|---:|---:|
| `1 000` | `1 000 000` |
| `2 000` | `4 000 000` |
| `8 000` | `64 000 000` |

Le point important est le passage à l'échelle. Ajouter du contexte ne coûte pas linéairement dans l'attention dense. Une séquence huit fois plus longue que `1 000` produit soixante-quatre fois plus de relations.

Ce calcul ne donne pas toute la latence réelle. Les kernels, le hardware, le batch, le nombre de têtes, la dimension cachée et les optimisations comptent. Mais il montre la pression structurelle.

## Points importants

- L'attention dense compare chaque position avec chaque position.
- Le nombre de relations croît comme `n^2`.
- Doubler la longueur quadruple le nombre de relations.
- `8 000` tokens donnent `64 000 000` relations.
- Les optimisations matérielles améliorent l'exécution, mais ne suppriment pas le principe quadratique de base.

## Prolongement

Ce coût explique pourquoi on explore des alternatives ou compléments : attention sparse, fenêtres locales, RAG, SSM, mémoire externe, résumé hiérarchique et architectures hybrides.
