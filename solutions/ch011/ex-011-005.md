# EX-011-005 - Transformer dans un système réel

## Énoncé

Dessinez ou décrivez une architecture minimale qui utilise un Transformer pour répondre à une question documentaire, mais qui inclut aussi récupération, validation, permissions, observabilité et budget d'inférence.

## Ce que l'exercice vérifie

L'exercice vérifie que le modèle n'est pas le système. Un Transformer peut générer une réponse, mais une application documentaire sérieuse doit gérer les sources, les droits, les traces, les coûts et la validation.

## Solution détaillée

Une architecture minimale pourrait ressembler à ceci :

```text
requête utilisateur
  -> validation d'entrée
  -> contrôle des permissions
  -> recherche documentaire
  -> sélection du contexte
  -> appel du Transformer
  -> vérification de la réponse
  -> journalisation et métriques
  -> réponse utilisateur
```

### Validation d'entrée

Le système vérifie que la requête est acceptable :

- taille raisonnable ;
- format valide ;
- absence de contenu interdit par la politique applicative ;
- utilisateur authentifié si nécessaire.

### Permissions

Avant de récupérer des documents, le système doit vérifier les droits.

Un utilisateur ne devrait pas pouvoir obtenir une réponse construite à partir de documents auxquels il n'a pas accès.

### Recherche documentaire

La récupération peut combiner :

- recherche vectorielle ;
- recherche lexicale ;
- filtres par métadonnées ;
- dates ;
- version ;
- permissions.

### Sélection du contexte

Le système choisit les passages à fournir au modèle. Il doit respecter un budget :

```text
taille maximale du prompt
nombre maximal de documents
coût maximal par requête
latence cible
```

### Appel du modèle

Le Transformer reçoit :

- la question ;
- les extraits autorisés ;
- les instructions de réponse ;
- les contraintes de citation.

### Vérification

Après génération, le système peut vérifier :

- citations présentes ;
- réponse supportée par les extraits ;
- absence de fuite de documents non autorisés ;
- format attendu ;
- niveau de confiance ou besoin d'escalade.

### Observabilité

Il faut journaliser :

- identifiant de requête ;
- utilisateur ou rôle, selon la politique de confidentialité ;
- documents récupérés ;
- versions de corpus ;
- latence ;
- coût ;
- modèle utilisé ;
- erreurs ;
- score de récupération.

## Points importants

- Le Transformer est une brique de génération, pas toute l'application.
- Les permissions doivent s'appliquer avant la récupération.
- La recherche documentaire doit être observable.
- Le budget d'inférence doit être explicite.
- Les réponses documentaires demandent des sources et des vérifications.

## Prolongement

Une version plus avancée pourrait ajouter un reranker, un cache, une politique de fraîcheur documentaire, un mode "je ne sais pas", un audit humain et des tests de non-régression sur questions sensibles.
