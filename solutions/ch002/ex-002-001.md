# EX-002-001 - Vérifier des shapes

## Énoncé

Pour cinq opérations de tenseurs ou matrices, indiquez si l'opération est valide et donnez la shape du résultat.

## Ce que l'exercice vérifie

L'exercice vérifie un réflexe indispensable : avant de parler de modèle, il faut savoir si les dimensions se parlent.

Dans un système ML, beaucoup de bogues ne viennent pas d'une idée mathématique complexe. Ils viennent d'un axe inversé, d'un batch oublié, d'une projection incompatible ou d'une concaténation faite au mauvais endroit.

## Solution détaillée

Voici cinq opérations représentatives.

### 1. Produit matriciel simple

On donne :

```text
A : (3, 4)
B : (4, 2)
```

Le produit `A @ B` est valide parce que la dimension interne correspond : `4` dans `A` et `4` dans `B`.

Résultat :

```text
A @ B : (3, 2)
```

Lecture pratique : chaque ligne de `A` est projetée vers un espace de dimension `2`.

### 2. Produit matriciel invalide

On donne :

```text
A : (3, 4)
C : (5, 2)
```

Le produit `A @ C` est invalide, car la dimension interne attendue ne correspond pas :

```text
4 != 5
```

Ce n'est pas une subtilité. Le calcul ne sait pas quelles composantes multiplier ensemble.

### 3. Batch de vecteurs par matrice de projection

On donne :

```text
X : (32, 10)
W : (10, 64)
```

`X` contient un batch de `32` exemples, chacun avec `10` features. `W` projette `10` features vers `64`.

Le produit est valide :

```text
X @ W : (32, 64)
```

Le batch est conservé. La dimension feature change.

### 4. Tenseur séquentiel par projection partagée

On donne :

```text
H : (16, 200, 768)
W : (768, 256)
```

On peut appliquer la projection sur la dernière dimension. Dans beaucoup de frameworks, cela revient à traiter toutes les positions `(batch, temps)` comme des lignes.

Résultat :

```text
H @ W : (16, 200, 256)
```

Le batch `16` et la longueur `200` restent inchangés. La représentation de chaque token passe de `768` à `256`.

### 5. Concaténation sur le mauvais axe

On donne :

```text
A : (32, 128)
B : (32, 64)
```

Concaténer sur l'axe des features est valide :

```text
concat_features(A, B) : (32, 192)
```

Concaténer sur l'axe batch donnerait :

```text
concat_batch(A, B)
```

Cette opération est invalide si on exige que les features correspondent, car `128 != 64`. Même si un framework permet certaines concaténations avec d'autres axes, l'intention serait suspecte : on mélangerait des exemples qui n'ont pas la même représentation.

## Points importants

- Pour `A : (m, n)` et `B : (n, p)`, `A @ B` donne `(m, p)`.
- La dimension interne doit correspondre.
- Le batch n'est généralement pas une dimension à projeter : il est transporté.
- Dans les tenseurs de séquence, la dernière dimension est souvent celle des features.
- Une opération valide syntaxiquement peut rester mauvaise architecturalement si elle mélange les axes.

## Prolongement

Dans un MoE, les shapes deviennent encore plus importantes. Un routeur peut produire :

```text
scores  : (batch, experts)
indices : (batch, k)
weights : (batch, k)
```

La difficulté n'est pas seulement de calculer les shapes. Il faut aussi savoir ce que chaque axe représente. Une shape sans sémantique, c'est juste une dimension qui attend de devenir un bogue.
