# EX-004-005 - Lien avec les réseaux continus

## Énoncé

Expliquez la différence entre `h_{k+1} = F_theta(h_k, x_k)` et `dh(t) / dt = f_theta(h(t), x(t), t)`.

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre une mise à jour discrète et une dynamique continue. C'est une distinction qui revient dans tout le reste du tome.

Les deux formulations manipulent un état, mais elles ne décrivent pas le temps de la même manière.

## Solution détaillée

La première formulation est :

```text
h_{k+1} = F_theta(h_k, x_k)
```

Elle décrit une mise à jour par pas. À l'étape `k`, le modèle prend l'état courant `h_k` et l'entrée `x_k`, puis calcule directement l'état suivant `h_{k+1}`.

C'est la logique de beaucoup de modèles discrets :

```text
état courant + entrée courante -> état suivant
```

Le temps est représenté par un index :

```text
k = 0, 1, 2, 3, ...
```

Cela convient très bien quand les observations sont naturellement régulières ou quand on accepte de les transformer en séquence discrète.

La deuxième formulation est :

```text
dh(t) / dt = f_theta(h(t), x(t), t)
```

Elle ne donne pas directement le prochain état. Elle donne la vitesse de changement de l'état au temps `t`.

Autrement dit :

```text
état courant + entrée + temps -> dérivée de l'état
```

Pour obtenir `h(t)` plus tard, il faut intégrer cette dynamique avec un solveur numérique.

La différence est importante.

Dans le modèle discret, `F_theta` contient toute la transition :

```text
h_k -> h_{k+1}
```

Dans le modèle continu, `f_theta` décrit une dynamique locale :

```text
comment h change maintenant
```

puis le solveur applique cette dynamique sur un intervalle de temps.

### Données régulières et irrégulières

Si les données arrivent toutes les secondes, un modèle discret peut être naturel :

```text
x_0, x_1, x_2, ...
```

Si les données arrivent à des temps irréguliers :

```text
t = 0.0, 0.1, 3.7, 3.9, 12.5
```

une formulation continue peut être plus expressive, car l'intervalle de temps devient une partie du problème.

Cela ne veut pas dire que les modèles continus sont toujours meilleurs. Ils ajoutent du coût numérique, des choix de solveur et parfois des difficultés d'entraînement.

### Coût et comportement

Dans une mise à jour discrète, le coût est souvent lié au nombre d'étapes de la séquence.

Dans une dynamique continue, le coût dépend aussi du solveur :

- taille des pas internes ;
- tolérance d'erreur ;
- rigidité de la dynamique ;
- nombre d'évaluations de `f_theta`.

Un modèle continu peut donc être élégant sur le papier et coûteux en pratique.

## Points importants

- `h_{k+1} = F_theta(h_k, x_k)` décrit une transition discrète.
- `dh(t)/dt = f_theta(h(t), x(t), t)` décrit une vitesse de changement continue.
- Le modèle continu nécessite un solveur pour produire des états.
- Les observations irrégulières rendent le temps continu particulièrement intéressant.
- Le temps continu ajoute aussi du coût et des risques numériques.

## Prolongement

Une lecture pragmatique est la suivante :

```text
discret : je définis le prochain état
continu : je définis comment l'état évolue
```

Cette différence prépare les chapitres sur Neural ODE, CT-RNN, LTC et CfC. Dans ces architectures, le temps n'est pas seulement un index de tableau. Il devient une variable de la dynamique.
