# EX-034-002 - Fiche dataset minimale

## Énoncé

Rédigez une datasheet simplifiée pour un dataset de logs applicatifs.

## Ce que l'exercice vérifie

L'exercice vérifie qu'un dataset doit être documenté comme un artefact technique, pas seulement stocké comme un fichier.

## Solution détaillée

### Nom

`app-logs-incident-v1`

### Motivation

Entraîner et évaluer un modèle de détection d'incidents applicatifs.

### Source

Logs applicatifs de services internes, collectés via pipeline d'observabilité.

### Période

```text
2025-01-01 à 2025-03-31
```

### Champs

```text
timestamp
service
environment
severity
message_template
http_status
latency_ms
correlation_id
deployment_version
incident_label
```

### Transformations

- suppression ou masquage des identifiants sensibles ;
- normalisation des timestamps ;
- regroupement par fenêtre temporelle ;
- extraction de features agrégées ;
- séparation train/validation/test temporelle.

### Données sensibles

Les messages bruts peuvent contenir des identifiants techniques. Ils doivent être masqués avant usage modèle.

### Usage prévu

Détection et analyse d'incidents applicatifs.

### Limites

- ne couvre pas tous les services ;
- biaisé par incidents déjà détectés ;
- labels potentiellement incomplets ;
- distribution future différente possible.

### Politique de suppression

Suppression des logs bruts après durée définie ; conservation des agrégats anonymisés selon politique interne.

## Points importants

- La période de collecte compte.
- Les transformations doivent être listées.
- Les champs sensibles doivent être identifiés.
- Les splits temporels évitent les fuites.
- Les limites doivent être explicites.

## Prolongement

Une datasheet utile doit être mise à jour quand le pipeline de collecte, les labels ou la politique de rétention changent.
