# EX-034-005 - Audit d'un incident

## Énoncé

Un utilisateur reçoit une réponse erronée fondée sur un document périmé. Décrivez les traces nécessaires pour diagnostiquer l'incident.

## Ce que l'exercice vérifie

L'exercice vérifie la traçabilité d'un système RAG ou agentique.

## Solution détaillée

Traces nécessaires :

```text
requête utilisateur
timestamp
utilisateur ou rôle
version du modèle
version du prompt
version du corpus
version de l'index
documents récupérés
scores de ranking
date des documents
extraits fournis au modèle
réponse générée
citations affichées
politique de fraîcheur
mémoire utilisée
outils appelés
logs de validation
```

Questions à poser :

1. Le document périmé était-il encore dans le corpus actif ?
2. L'index avait-il été reconstruit après suppression ou expiration ?
3. Le reranker a-t-il favorisé un document ancien ?
4. La politique de fraîcheur était-elle absente ou mal appliquée ?
5. Le modèle a-t-il cité le document correctement ou l'a-t-il amplifié ?
6. Une mémoire persistante contenait-elle une synthèse ancienne ?

Correction :

- invalider le document ;
- reconstruire l'index ;
- ajouter un filtre de fraîcheur ;
- corriger ou supprimer la mémoire dérivée ;
- ajouter un test de non-régression.

## Points importants

- Il faut tracer corpus, index et documents récupérés.
- La date du document est essentielle.
- La mémoire peut contenir une ancienne synthèse.
- La citation ne suffit pas si la source est périmée.
- L'incident doit produire un test de régression.

## Prolongement

Un système documentaire fiable doit savoir non seulement citer, mais aussi vérifier si la source citée est encore valable.
