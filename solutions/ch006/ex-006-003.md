# EX-006-003 - Interpréter une courbe de surapprentissage

## Énoncé

Expliquez ce que vous concluez si la loss d'entraînement baisse pendant que la loss de validation augmente depuis plusieurs epochs.

## Ce que l'exercice vérifie

L'exercice vérifie le diagnostic de généralisation. Une bonne perte d'entraînement ne suffit pas. Le modèle doit fonctionner sur des données qu'il n'a pas utilisées pour ajuster ses poids.

## Solution détaillée

Si la loss d'entraînement baisse, le modèle apprend à mieux prédire les exemples du train set.

Si en même temps la loss de validation augmente, le modèle se comporte de plus en plus mal sur des données séparées. Le diagnostic le plus probable est le surapprentissage.

Cela signifie que le modèle commence à exploiter des détails propres au train set :

- bruit ;
- exemples atypiques ;
- corrélations accidentelles ;
- fuites indirectes ;
- distribution trop spécifique.

Mais il ne faut pas conclure trop vite. Une courbe est un signal, pas une preuve complète. Il faut vérifier :

- que le split train/validation est correct ;
- que la validation représente bien le problème réel ;
- qu'il n'y a pas de fuite de données ;
- que les métriques sont calculées de la même façon ;
- que la distribution ne change pas fortement entre train et validation.

Actions possibles :

1. Activer ou renforcer l'early stopping.
2. Réduire la taille du modèle.
3. Ajouter de la régularisation L2 ou dropout.
4. Augmenter ou nettoyer les données.
5. Revoir les features et les fuites possibles.
6. Mesurer par sous-groupes plutôt que seulement en moyenne.

La mauvaise réaction serait d'augmenter encore la taille du modèle sans diagnostic. Si le modèle a déjà trop de capacité par rapport aux données, plus de capacité peut aggraver le problème.

## Points importants

- Train qui baisse et validation qui monte signale souvent du surapprentissage.
- Il faut vérifier les données avant d'accuser seulement le modèle.
- L'early stopping est une première réponse simple.
- La régularisation réduit la tendance à mémoriser.
- Les métriques de validation doivent refléter l'usage réel.

## Prolongement

En production, il faut aussi surveiller une validation temporelle ou un jeu hors distribution. Un modèle peut bien généraliser sur une validation construite trop près du train set, puis échouer quand les données changent vraiment.
