# EX-006-002 - Lire une architecture MLP

## Énoncé

Décrivez les dimensions des matrices pour un MLP qui reçoit 10 features, possède une couche cachée de 32 neurones, une deuxième couche cachée de 16 neurones, et produit 3 scores de sortie.

## Ce que l'exercice vérifie

L'exercice vérifie la lecture des dimensions. Un MLP est simple conceptuellement, mais les erreurs de shape restent très fréquentes.

## Solution détaillée

L'entrée contient 10 features :

```text
x : (10)
```

Pour un batch de `B` exemples :

```text
X : (B, 10)
```

La première couche projette de 10 vers 32 :

```text
W1 : (10, 32)
b1 : (32)
H1 = activation(X @ W1 + b1)
H1 : (B, 32)
```

La deuxième couche projette de 32 vers 16 :

```text
W2 : (32, 16)
b2 : (16)
H2 = activation(H1 @ W2 + b2)
H2 : (B, 16)
```

La couche de sortie projette de 16 vers 3 :

```text
W3 : (16, 3)
b3 : (3)
Y = H2 @ W3 + b3
Y : (B, 3)
```

Les 3 sorties peuvent représenter trois scores de classes, avant softmax par exemple.

Attention : certains frameworks stockent les poids avec une convention transposée. Le contrat conceptuel reste le même : chaque couche transforme une dimension d'entrée en une dimension de sortie.

## Points importants

- La première couche mappe `10 -> 32`.
- La deuxième couche mappe `32 -> 16`.
- La sortie mappe `16 -> 3`.
- Les biais ont la taille de la dimension de sortie.
- Le batch reste transporté : il ne devient pas une feature.

## Prolongement

Une bonne documentation de modèle devrait dire explicitement :

```text
input:  (batch, 10)
hidden: (batch, 32)
hidden: (batch, 16)
output: (batch, 3)
```

Ce genre de description évite beaucoup de bogues, surtout quand le modèle devient modulaire.
