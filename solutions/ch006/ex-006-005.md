# EX-006-005 - Choisir une régularisation

## Énoncé

Vous avez un MLP qui obtient une très bonne performance train, mais une validation instable. Proposez trois actions concrètes avant d'augmenter encore la taille du modèle.

## Ce que l'exercice vérifie

L'exercice vérifie une discipline d'ingénierie : ne pas répondre à un problème de généralisation par plus de capacité sans diagnostic.

## Solution détaillée

Première action : vérifier les données et les splits.

Avant de modifier le modèle, il faut vérifier que le problème mesuré est réel :

- séparation train/validation correcte ;
- absence de fuite de données ;
- classes représentées dans les deux jeux ;
- distribution temporelle respectée si les données sont temporelles ;
- transformations identiques entre train et validation.

Une validation instable peut venir d'un modèle fragile, mais aussi d'un jeu de validation trop petit ou mal construit.

Deuxième action : ajouter une stratégie d'early stopping.

Si la validation se dégrade après un certain nombre d'epochs, on conserve le meilleur checkpoint au lieu de garder le dernier. C'est simple, efficace, et souvent plus utile que d'ajouter des couches.

On peut suivre :

```text
validation_loss
F1-score
precision-recall
métrique métier
```

Le point important est de choisir la métrique qui reflète l'usage réel.

Troisième action : renforcer la régularisation.

Options classiques :

- L2 weight decay ;
- dropout ;
- réduction de la taille du MLP ;
- augmentation de données si elle est valide ;
- normalisation des entrées ;
- nettoyage des labels douteux.

Réduire le modèle peut sembler contre-intuitif, mais si le modèle mémorise trop, moins de capacité peut améliorer la généralisation.

## Points importants

- Vérifier les données avant d'accuser l'architecture.
- Early stopping évite de garder un modèle trop spécialisé sur le train.
- La régularisation limite la mémorisation.
- Augmenter la taille du modèle peut aggraver le problème.
- Une validation instable doit être analysée par sous-groupes et dans le temps.

## Prolongement

Un protocole propre pourrait comparer quatre variantes :

```text
baseline actuelle
baseline + early stopping
baseline + L2/dropout
modèle plus petit + régularisation
```

On ne choisit pas au feeling. On choisit avec une métrique, un budget et une validation crédible.
