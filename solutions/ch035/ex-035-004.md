# EX-035-004 - Lire une phrase avec LOTAD

## Énoncé

Analysez la phrase : « Ne redémarre pas le service tout de suite ; vérifie d'abord si la mémoire monte depuis le dernier déploiement. »

## Ce que l'exercice vérifie

L'exercice vérifie le rôle architectural de LOTAD : relier tokens, objets, concepts, attention et intention opérationnelle.

## Solution détaillée

Phrase :

```text
Ne redémarre pas le service tout de suite ;
vérifie d'abord si la mémoire monte depuis le dernier déploiement.
```

Analyse token/concept :

| Élément | Rôle |
|---|---|
| `Ne redémarre pas` | contrainte négative, action interdite temporairement |
| `service` | objet cible à résoudre |
| `tout de suite` | contrainte temporelle |
| `vérifie d'abord` | priorité d'action |
| `mémoire monte` | signal métrique à observer |
| `dernier déploiement` | événement causal candidat |

LOTAD devrait relier :

```text
action: restart(service) -> interdit maintenant
action: check(memory_trend) -> prioritaire
event: last_deployment -> point de référence
metric: memory -> tendance à comparer
intent: diagnostiquer avant agir
```

OAD rattache `service`, `mémoire` et `déploiement` à des objets/concepts. ECAD peut ensuite poser une hypothèse causale :

```text
dernier déploiement -> possible cause -> hausse mémoire
```

Mais l'action ne doit pas être prise sans vérification. La phrase exprime une intention d'ordre opérationnel : ne pas appliquer une action destructive avant diagnostic.

## Points importants

- LOTAD relie tokens, objets et intention.
- La négation est centrale : ne pas redémarrer.
- Le déploiement est un repère temporel et causal candidat.
- ECAD peut formuler l'hypothèse, pas la prouver seul.
- La sortie attendue est un plan de vérification, pas une action immédiate.

## Prolongement

Un bon test consisterait à vérifier que le système ne propose pas un redémarrage comme première action, mais demande les métriques mémoire depuis le déploiement.
