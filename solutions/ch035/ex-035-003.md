# EX-035-003 - Séparer les projections du monde

## Énoncé

Choisissez un objet technique, par exemple un service de facturation. Décrivez ce que WoE, WoB, WoG, WoV et WoS devraient porter pour cet objet.

## Ce que l'exercice vérifie

L'exercice vérifie la séparation des projections du monde dans l'étude de cas Qaya. Chaque projection porte un type de signal différent.

## Solution détaillée

Objet : service de facturation `Billing.Api`.

### WoE - World object Embedding

Représentation vectorielle du service :

```text
nom, domaine, endpoints, logs, incidents, dépendances textuelles
```

Elle sert à retrouver ou rapprocher des objets similaires.

### WoB - World object Bayesian

Vue probabiliste :

```text
probabilité d'incident
probabilité de cause liée à DB
confiance dans l'état courant
incertitude des observations
```

### WoG - World object GNN + K-Means

Vue relationnelle et exploratoire :

```text
Billing.Api -> dépend de -> PaymentGateway
Billing.Api -> écrit dans -> InvoiceDb
Billing.Api -> exposé par -> ApiGateway
```

Le clustering peut proposer des liens, mais ces liens doivent être validés.

### WoV - World object Vision

Si le service est visible dans un dashboard ou une topologie, WoV peut porter :

```text
captures d'écran
état visuel de dashboard
graphe de dépendances affiché
alertes visuelles
```

### WoS - World object Sound

Si des signaux sonores existent :

```text
alertes audio
signaux opérateur
flux vocal incident
```

Dans la plupart des systèmes logiciels, WoS peut être vide ou peu utilisé.

## Points importants

- WoE encode la proximité vectorielle.
- WoB porte l'incertitude.
- WoG porte relations et liens candidats.
- WoV porte la perception visuelle.
- WoS porte la perception sonore.
- Les projections ne doivent pas être confondues avec la vérité complète de l'objet.

## Prolongement

Un objet technique sérieux doit avoir provenance, version et qualité de chaque projection. WoG peut suggérer des liens, mais l'observabilité doit dire s'ils sont confirmés ou spéculatifs.
