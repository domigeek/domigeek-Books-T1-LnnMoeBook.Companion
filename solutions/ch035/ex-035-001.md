# EX-035-001 - Tracer un flux vidéo comme événements

## Énoncé

Décrivez comment un flux vidéo découpé en fragments peut être transformé en `EventEnvelope`, relié par `correlationId`, attaché à une fenêtre d'attention, puis traité par ED, OAD, WoV et ECAD.

## Ce que l'exercice vérifie

L'exercice vérifie la lecture événementielle de Qaya : même un flux vidéo peut être converti en événements structurés avant d'entrer dans les composants dynamiques.

## Solution détaillée

Un flux vidéo peut être découpé en fragments :

```text
frame batch
segment temporel
datagram
chunk encodé
```

Chaque fragment devient une enveloppe :

```json
{
  "eventId": "evt_00042",
  "correlationId": "video_stream_17_window_003",
  "sequence": 42,
  "timestamp": "2026-06-11T18:00:00Z",
  "type": "VisionFrameChunk",
  "payload": {
    "frameRange": [420, 439],
    "embeddingRef": "vec_abc",
    "metadata": {
      "source": "camera_1",
      "fps": 30
    }
  }
}
```

Le `correlationId` relie les fragments appartenant à la même fenêtre d'attention. Le compteur `sequence` permet de reconstruire l'ordre.

Traitement :

```text
EventEnvelope -> ED -> fenêtre d'attention -> OAD/WoV -> ECAD
```

- ED traite l'événement comme unité de dynamique.
- OAD rattache l'événement à des objets ou concepts suivis.
- WoV porte la projection vision du monde observé.
- ECAD peut relier certains événements à des hypothèses causales opérationnelles.

Le son ou la vision ne contournent pas ED. Ils arrivent dans le payload d'événements structurés.

## Points importants

- Un flux vidéo peut devenir une série d'événements.
- Le payload transporte les données ou références lourdes.
- Le `correlationId` relie les fragments.
- ED reste le point de passage événementiel.
- WoV est une projection vision, pas toute l'architecture.

## Prolongement

Un prototype vérifiable devrait rejouer un flux enregistré et contrôler ordre, pertes, latence, association aux objets et cohérence du `correlationId`.
