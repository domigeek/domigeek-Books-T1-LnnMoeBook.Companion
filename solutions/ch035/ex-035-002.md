# EX-035-002 - Concevoir une politique ED anti-bruit

## Énoncé

Proposez une règle de traitement pour trois flux : heartbeat fréquent, métrique RAM, événement rare critique.

## Ce que l'exercice vérifie

L'exercice vérifie l'intérêt d'ED : un événement n'a pas seulement un temps, il a aussi une importance, une fréquence et un effet sur la dynamique.

## Solution détaillée

Politique possible :

| Flux | Fréquence | Traitement ED |
|---|---:|---|
| Heartbeat | très fréquent | compacter, échantillonner, faible poids |
| RAM | régulier | agréger par tendance et seuils |
| Événement critique | rare | poids élevé, fenêtre dédiée, alerte |

Pour le heartbeat :

```text
ne pas injecter chaque battement dans l'état profond
conserver dernier timestamp, taux de perte, dérive
```

Pour la RAM :

```text
suivre moyenne, pente, seuil, accélération
```

Pour l'événement critique :

```text
ouvrir ou renforcer une fenêtre d'attention
lier aux événements précédents par correlationId
déclencher ECAD pour hypothèses causales
```

Le but est d'éviter deux erreurs :

- les événements fréquents diluent tout ;
- les événements rares arrivent trop tard dans la dynamique.

## Points importants

- Tous les événements ne doivent pas peser pareil.
- La fréquence doit influencer le traitement.
- Les heartbeats doivent souvent être compactés.
- Les événements rares critiques doivent être préservés.
- Les règles ED doivent être observables.

## Prolongement

La politique peut être comparée à une baseline naïve qui injecte tous les événements de la même manière. Si ED n'améliore pas robustesse ou latence, la règle doit être revue.
