# EX-022-003 - Concurrence ou coopération

## Énoncé

Pour une tâche de traduction multilingue, proposez une topologie concurrente et une topologie coopérative. Expliquez leurs compromis.

## Ce que l'exercice vérifie

L'exercice vérifie deux façons d'organiser des experts : choisir entre eux ou les faire contribuer ensemble.

## Solution détaillée

### Topologie concurrente

Le routeur sélectionne un expert selon la langue ou le régime :

```text
français -> expert roman
japonais -> expert CJK
arabe -> expert sémitique
```

Avantage :

- coût actif faible ;
- routage lisible ;
- spécialisation potentielle.

Risques :

- mauvais routage ;
- expert peu entraîné pour langues rares ;
- frontières floues pour textes mixtes ;
- surcharge de certains experts.

### Topologie coopérative

On combine un expert général et un expert spécialisé :

```text
expert général + expert langue/source + expert style
```

Avantage :

- robustesse ;
- partage de connaissances communes ;
- meilleure gestion des cas mixtes.

Risques :

- coût actif plus élevé ;
- recombinaison plus complexe ;
- interprétation moins simple ;
- besoin de load balancing.

## Points importants

- Concurrence : choisir quelques experts.
- Coopération : combiner plusieurs contributions.
- La concurrence réduit le coût mais augmente le risque de mauvais choix.
- La coopération peut être plus robuste mais coûte plus cher.
- Les textes multilingues rendent les frontières d'experts délicates.

## Prolongement

Un bon protocole testerait les langues fréquentes, rares, mixtes, dialectales et les changements de domaine. Une topologie qui marche sur anglais-français ne prouve pas grand-chose pour tout le multilingue.
