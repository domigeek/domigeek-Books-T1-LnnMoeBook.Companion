# EX-030-003 - Baseline pipeline

## Énoncé

Proposez un pipeline statique de référence pour le même problème que votre hybride. Expliquez quelles métriques permettraient de justifier le passage à un routage dynamique.

## Ce que l'exercice vérifie

L'exercice vérifie que l'hybride doit battre un pipeline simple. Une architecture dynamique n'est pas justifiée tant qu'une chaîne statique fait le travail.

## Solution détaillée

Pipeline statique :

```text
entrée
  -> validation
  -> classification simple de tâche
  -> récupération mémoire si mot-clé ou règle
  -> expert fixe selon type de tâche
  -> vérification
  -> réponse
```

Exemple :

- si la demande contient du code, appeler `ExpertCode` ;
- si elle contient des logs, appeler `ExpertOps` ;
- si elle demande une source, appeler `ExpertMemory` ;
- toujours passer par `ExpertSafety`.

Métriques pour justifier le routage dynamique :

| Métrique | Pourquoi |
|---|---|
| Qualité par type de tâche | vérifier que l'hybride répond mieux |
| Latence p95/p99 | éviter un gain qualitatif trop coûteux |
| Coût par requête | mesurer appels experts et mémoire |
| Taux de mauvais routage | mesurer la précision du routeur |
| Robustesse aux contextes ambigus | tester là où le statique devrait échouer |
| Taux de fallback | mesurer les limites pratiques |

Condition d'acceptation possible :

```text
passer au dynamique seulement si :
  qualité +5 % sur tâches ambiguës,
  latence p95 < seuil,
  coût moyen < budget,
  aucun recul sur tâches simples,
  traces exploitables en revue d'incident.
```

## Points importants

- Le pipeline statique est la baseline.
- Le routage dynamique doit améliorer des cas précis.
- Les tâches simples ne doivent pas régresser.
- La latence et le coût font partie du verdict.
- Le routage doit être observable.

## Prolongement

Un hybride utile ne remplace pas tout. Il peut être activé seulement sur les cas où le pipeline statique montre ses limites.
