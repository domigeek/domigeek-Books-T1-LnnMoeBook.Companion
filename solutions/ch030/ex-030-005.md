# EX-030-005 - Statut scientifique

## Énoncé

Classez dix affirmations sur LNN + MoE en trois catégories : établi, hypothétique, choix d'architecture.

## Ce que l'exercice vérifie

L'exercice vérifie la discipline de statut. Une architecture proposée ne doit pas être présentée comme un résultat démontré.

## Solution détaillée

| Affirmation | Catégorie | Justification |
|---|---|---|
| Les MoE activent un sous-ensemble d'experts | Établi | principe documenté dans la littérature MoE |
| Les LNN modélisent des dynamiques temporelles continues | Établi | selon les formulations publiées |
| Un hybride LNN + MoE peut utiliser l'état temporel pour router | Choix d'architecture | proposition de design |
| Cet hybride est toujours meilleur qu'un Transformer dense | Hypothétique | dépend des tâches et métriques |
| Le routage sparse réduit le calcul actif par token | Établi | vrai sous hypothèses de sparsité |
| Le coût système d'un MoE peut rester élevé | Établi | mémoire, dispatch, communication |
| Un état LNN améliore forcément l'interprétabilité | Hypothétique | il faut des tests et des liens entrée-sortie |
| Un orchestrateur dynamique peut être plus robuste sur événements irréguliers | Hypothétique | plausible, mais à valider |
| Journaliser le routage est nécessaire pour exploiter le système | Choix d'architecture solide | exigence d'opérabilité |
| Qaya illustre une façon d'assembler ces briques | Choix d'architecture | étude de cas, pas preuve générale |

## Points importants

- Établi : résultat ou mécanisme bien documenté.
- Hypothétique : plausible mais non démontré dans ce cadre.
- Choix d'architecture : décision de design.
- Une proposition peut être intéressante sans être une preuve.
- Les métriques déterminent la portée des conclusions.

## Prolongement

Cette classification devrait accompagner tout chapitre d'architecture avancée. Elle évite de transformer une bonne intuition en affirmation trop large.
