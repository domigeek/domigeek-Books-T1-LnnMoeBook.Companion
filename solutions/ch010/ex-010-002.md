# EX-010-002 - Reset gate

## Énoncé

Donnez un exemple de séquence où il est utile de réduire l'influence de l'état précédent pour construire le nouvel état candidat.

## Ce que l'exercice vérifie

L'exercice vérifie l'utilité de la reset gate : parfois, le passé immédiat ne doit pas trop influencer la construction du nouveau candidat.

## Solution détaillée

Prenons une séquence de requêtes utilisateur dans un assistant technique.

Les premières requêtes concernent un problème de base de données :

```text
requête lente
index manquant
plan d'exécution
```

Puis l'utilisateur change complètement de sujet :

```text
comment configurer un pipeline CI
```

Quand le modèle construit le nouvel état candidat pour cette nouvelle requête, il peut être utile de réduire l'influence de l'état précédent. Sinon, le contexte "base de données" risque de polluer la représentation de la question CI.

La reset gate du GRU sert précisément à moduler l'utilisation de l'ancien état dans la construction du candidat `g_t`.

Autre exemple : logs applicatifs.

Une séquence peut contenir une phase normale, puis un redémarrage du service. Après le redémarrage, certaines informations précédentes deviennent moins pertinentes. Le modèle doit reconnaître une rupture de régime.

## Points importants

- La reset gate aide à construire un candidat moins dépendant de l'ancien état.
- Elle est utile lors d'un changement de contexte.
- Elle ne supprime pas nécessairement toute mémoire.
- Elle module l'influence du passé sur le candidat.
- C'est différent de la update gate, qui contrôle le mélange final.

## Prolongement

Dans une architecture logicielle explicite, on aurait parfois un événement `ContextReset` ou `SessionChanged`. Dans un GRU, cette décision est apprise de manière latente à partir des données.
