# EX-029-004 - Concevoir un protocole de test

## Énoncé

Proposez un protocole minimal pour tester si une adaptation dynamique de type Transformer² apporte un gain sur un assistant de code.

## Ce que l'exercice vérifie

L'exercice vérifie la capacité à tester une architecture d'adaptation sans se laisser impressionner par le mécanisme. Le protocole doit mesurer qualité, coût, stabilité et erreurs.

## Solution détaillée

### Tâches de test

Il faut couvrir plusieurs catégories :

```text
correction de bogue
génération de fonction
refactoring
écriture de tests
explication de code
modification multi-fichiers
diagnostic d'erreur de compilation
```

Si le test ne couvre qu'un seul type de tâche, l'adaptation peut sembler bonne simplement parce qu'elle est spécialisée sur ce cas.

### Baselines

Baseline 1 :

```text
même modèle sans adaptation dynamique
```

Baseline 2 :

```text
même modèle avec prompt spécialisé par tâche
```

Éventuellement baseline 3 :

```text
modèle plus petit ou plus grand sans adaptation
```

Cela permet de savoir si le gain vient vraiment de l'adaptation ou seulement d'un meilleur prompt ou d'une capacité différente.

### Métriques qualité

Pour un assistant de code, les métriques doivent être vérifiables :

- compilation ;
- tests unitaires passés ;
- taux de correction de bogue ;
- absence de régression ;
- conformité au style du dépôt ;
- nombre de tentatives nécessaires ;
- exactitude de l'explication si demandée.

### Métriques système

Il faut aussi mesurer :

- latence ;
- coût tokens ou calcul ;
- mémoire ;
- temps d'adaptation ;
- taux d'échec de dispatch ;
- stabilité entre runs.

### Analyse des erreurs

Classer les erreurs :

```text
mauvaise compréhension de la tâche
mauvais fichier modifié
code qui ne compile pas
test manquant
régression comportementale
adaptation inutile ou nuisible
```

Le protocole doit inclure des tâches où l'adaptation ne devrait pas aider. Sinon, on ne sait pas si le mécanisme sait rester sobre.

## Points importants

- Tester plusieurs familles de tâches.
- Comparer avec un modèle sans adaptation.
- Comparer avec un prompt spécialisé.
- Mesurer compilation et tests, pas seulement préférence humaine.
- Mesurer aussi coût et latence.
- Analyser les erreurs d'adaptation.

## Prolongement

Une conclusion correcte pourrait être :

```text
L'adaptation dynamique améliore les corrections multi-fichiers, mais n'apporte pas de gain sur les fonctions simples et augmente la latence de 18 %.
```

C'est ce genre de conclusion qui aide à décider, pas une phrase générale sur une architecture "plus intelligente".
