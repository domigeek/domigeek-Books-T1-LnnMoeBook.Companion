# EX-031-003 - Séparer épisode et connaissance

## Énoncé

À partir de cinq événements utilisateur, décidez lesquels restent épisodiques et lesquels peuvent produire une synthèse sémantique.

## Ce que l'exercice vérifie

L'exercice vérifie la séparation entre un événement vécu dans une session et une connaissance durable.

## Solution détaillée

Événements :

```text
E1: l'utilisateur demande comment configurer Serilog.
E2: l'utilisateur corrige le nom du projet : Billing.Api.
E3: l'utilisateur teste une hypothèse fausse sur Redis.
E4: l'utilisateur confirme que les logs doivent être en JSON.
E5: l'utilisateur colle une clé API par erreur.
```

Classification :

| Événement | Traitement |
|---|---|
| E1 | épisodique, utile au contexte récent |
| E2 | synthèse sémantique possible : nom du projet |
| E3 | épisodique ou connaissance négative si validée |
| E4 | synthèse sémantique : préférence technique confirmée |
| E5 | ne pas stocker, masquer, déclencher politique sécurité |

Synthèses possibles :

```text
Projet courant : Billing.Api.
Préférence de logs : format JSON.
```

On ne doit pas transformer chaque événement en connaissance. Une hypothèse fausse doit être marquée comme telle ou oubliée. Une donnée sensible doit être rejetée.

## Points importants

- Un épisode décrit ce qui s'est passé.
- Une connaissance résume ce qui reste vrai ou utile.
- Les confirmations sont plus solides que les hypothèses.
- Les secrets ne doivent pas devenir mémoire.
- La provenance doit être conservée.

## Prolongement

Une bonne mémoire persistante conserve la source de la synthèse. Sinon, on ne sait plus pourquoi le système croit savoir quelque chose.
