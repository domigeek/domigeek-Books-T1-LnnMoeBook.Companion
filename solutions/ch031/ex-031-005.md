# EX-031-005 - Concevoir un registre d'écriture mémoire

## Énoncé

Définissez un contrat d'écriture pour mémoire persistante.

## Ce que l'exercice vérifie

L'exercice vérifie qu'une mémoire persistante doit contrôler ce qui est écrit, par qui, pourquoi et pour combien de temps.

## Solution détaillée

Contrat minimal :

```json
{
  "memoryId": "mem_123",
  "type": "project_preference",
  "content": "Les logs du projet Billing.Api doivent être en JSON.",
  "source": "conversation:abc",
  "createdAt": "2026-06-11T18:00:00Z",
  "createdBy": "memory_writer",
  "confidence": 0.86,
  "scope": "project",
  "permissions": ["project:billing"],
  "expiresAt": null,
  "status": "active",
  "reviewRequired": false
}
```

Champs importants :

- type de mémoire ;
- contenu ;
- source ;
- confiance ;
- portée ;
- permissions ;
- date ;
- expiration ;
- statut ;
- politique de suppression.

Le registre doit aussi conserver les opérations :

```text
created
updated
invalidated
deleted
merged
```

Chaque écriture devrait passer par une validation :

- pas de secret ;
- pas de donnée sensible non autorisée ;
- source suffisante ;
- conflit vérifié ;
- expiration définie si information temporaire.

## Points importants

- Une mémoire persistante doit avoir un contrat d'écriture.
- La source et les permissions sont indispensables.
- Les suppressions doivent être traçables.
- Les conflits doivent être gérés.
- Une mémoire non gouvernée devient vite toxique.

## Prolongement

Dans une architecture agentique, l'écriture mémoire devrait être plus contrôlée que la lecture. Écrire, c'est modifier le comportement futur du système.
