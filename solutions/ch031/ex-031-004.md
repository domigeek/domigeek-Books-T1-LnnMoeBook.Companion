# EX-031-004 - Diagnostiquer un RAG défaillant

## Énoncé

On vous donne un système RAG qui répond avec assurance mais cite des sources faibles.

## Ce que l'exercice vérifie

L'exercice vérifie le diagnostic d'un RAG : une réponse bien formulée ne suffit pas si les sources sont mauvaises.

## Solution détaillée

Vérifications à faire :

```text
requête utilisateur
documents récupérés
scores de récupération
rang des sources citées
fraîcheur des documents
permissions
prompt envoyé au modèle
réponse finale
citations utilisées
```

Pseudo-code de diagnostic :

```text
result = search(query, topK=10)
for doc in result:
    print(doc.id, doc.score, doc.date, doc.source, doc.permissions)

answer = generate(query, result.top_context)
support = verify_claims(answer, result.top_context)

if support.low:
    return "réponse non suffisamment supportée"
```

Causes possibles :

- mauvais embedding ;
- corpus incomplet ;
- chunking trop petit ou trop grand ;
- documents périmés ;
- reranker absent ;
- prompt qui encourage trop la réponse ;
- modèle qui ignore les sources faibles ;
- absence de seuil minimal de score.

Mitigations :

- ajouter un seuil de récupération ;
- demander au modèle de refuser si sources insuffisantes ;
- ajouter reranking ;
- afficher les citations ;
- tester avec un jeu de questions annotées ;
- mesurer precision@k et recall@k.

## Points importants

- RAG défaillant peut générer une réponse confiante.
- La qualité des sources doit être mesurée.
- Les documents périmés sont un risque central.
- Un seuil de refus est souvent nécessaire.
- La vérification des claims aide à éviter les réponses non supportées.

## Prolongement

Un bon RAG doit savoir répondre : "je n'ai pas trouvé de source suffisante". C'est souvent plus professionnel qu'une réponse brillante et fausse.
