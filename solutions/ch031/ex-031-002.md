# EX-031-002 - Définir une politique d'oubli contrôlé

## Énoncé

Concevez une politique d'oubli pour une mémoire persistante de projet.

## Ce que l'exercice vérifie

L'exercice vérifie que la mémoire persistante doit avoir une politique de vie, pas seulement une fonction d'ajout.

## Solution détaillée

Une politique d'oubli peut définir plusieurs classes de mémoire.

| Type | Durée | Suppression | Exemple |
|---|---:|---|---|
| Épisode temporaire | 30 jours | automatique | trace d'une session de travail |
| Décision de projet | durable | revue manuelle | choix d'architecture validé |
| Préférence utilisateur | jusqu'à révocation | correction explicite | style de réponse préféré |
| Secret ou donnée sensible | ne pas stocker | rejet ou masquage | clé API |
| Fait incertain | court terme | expiration rapide | hypothèse non validée |

Contrat d'écriture :

```text
memory_id
type
source
created_at
expires_at
confidence
owner
permissions
delete_policy
```

Critères d'oubli :

- expiration ;
- faible confiance ;
- source périmée ;
- demande utilisateur ;
- conflit avec une information plus récente ;
- donnée sensible détectée.

## Points importants

- La mémoire doit oublier par conception.
- Toutes les informations n'ont pas la même durée de vie.
- Les données sensibles ne doivent pas être stockées par défaut.
- La suppression doit être traçable.
- La correction doit être possible.

## Prolongement

Un système sans oubli contrôlé finit par accumuler du bruit. Une mémoire utile n'est pas une pile infinie : c'est un registre gouverné.
