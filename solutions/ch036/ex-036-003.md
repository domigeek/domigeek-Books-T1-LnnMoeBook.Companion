# EX-036-003 - Tracer une courbe de perte

## Énoncé

À partir des `LossByEpoch` déjà exposés par certains exemples, produisez une courbe simple de perte initiale vers perte finale.

## Ce que l'exercice vérifie

L'exercice vérifie que l'on sait transformer un signal d'entraînement en diagnostic visuel. Une perte finale isolée ne dit pas grand-chose. Une courbe permet de voir si la perte descend régulièrement, oscille, explose, stagne ou descend seulement au début.

## Solution détaillée

Dans le dépôt compagnon, certains exemples peuvent nommer l'historique `LossByEpoch`, d'autres `LossHistory`. Le principe reste le même : il faut récupérer une séquence de nombres, l'associer à un index d'époque ou d'itération, puis produire une sortie lisible.

Pour l'exemple LTC, `TrainingReport` expose un historique de perte. Une première sortie très simple peut être un CSV :

```csv
epoch,loss
0,1.2481
1,0.9342
2,0.7215
3,0.5884
...
```

Un exemple C# minimal :

```csharp
var report = SimpleLtcCell.RunDefault();

var rows = new List<string> { "epoch,loss" };
for (var i = 0; i < report.LossHistory.Count; i++)
{
    rows.Add($"{i},{report.LossHistory[i].ToString(CultureInfo.InvariantCulture)}");
}

File.WriteAllLines("loss-ltc.csv", rows);
```

Ce fichier suffit déjà à produire une courbe avec un outil externe. Par exemple, avec Python et Matplotlib :

```python
import csv
import matplotlib.pyplot as plt

epochs = []
losses = []

with open("loss-ltc.csv", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    for row in reader:
        epochs.append(int(row["epoch"]))
        losses.append(float(row["loss"]))

plt.figure(figsize=(7, 4))
plt.plot(epochs, losses, marker="o", linewidth=1.5)
plt.xlabel("Itération")
plt.ylabel("Perte MSE")
plt.title("Perte d'entraînement - cellule LTC simplifiée")
plt.grid(True, alpha=0.3)
plt.tight_layout()
plt.savefig("loss-ltc.svg")
```

La figure doit montrer trois informations :

- la perte initiale ;
- la tendance générale ;
- la perte finale.

Si la courbe descend fortement puis stagne, le modèle apprend quelque chose au début puis atteint une limite. Si elle oscille violemment, le taux d'apprentissage est peut-être trop élevé. Si elle explose, il faut suspecter un problème numérique, un gradient instable ou une configuration incohérente. Si elle reste plate, il faut vérifier les gradients, la donnée synthétique, les paramètres entraînables et le calcul de perte.

Une courbe utile doit aussi éviter deux erreurs fréquentes.

La première erreur consiste à lisser trop tôt. Un lissage peut rendre une courbe plus jolie, mais masquer une instabilité. Pour un dépôt compagnon, il vaut mieux d'abord afficher la courbe brute.

La deuxième erreur consiste à comparer deux courbes sans même protocole. Si le MLP est entraîné pendant 20 itérations et le LTC pendant 100, la comparaison visuelle peut être trompeuse. Il faut annoter la figure ou conserver les paramètres d'entraînement dans un fichier voisin.

## Critères d'acceptation

Une solution acceptable produit :

- un fichier CSV ou JSON contenant l'historique de perte ;
- une figure SVG, PNG ou PDF ;
- un titre explicite ;
- des axes nommés ;
- une courbe qui inclut l'état initial et l'état final ;
- une note précisant le modèle, le nombre d'itérations et le taux d'apprentissage.

## Points importants

La courbe de perte n'est pas une preuve de généralisation. Elle montre seulement que l'optimisation a fait quelque chose sur le problème mesuré. Dans un livre technique, c'est déjà précieux : le lecteur voit le moteur tourner au lieu de seulement lire une équation.

## Prolongement

On peut enrichir la figure avec deux séries : perte d'entraînement et perte de validation. Même sur données synthétiques, cela aide à introduire la différence entre apprendre un signal et mémoriser un jeu d'exemples.
