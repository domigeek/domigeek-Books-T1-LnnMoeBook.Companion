# EX-008-005 - Diagnostiquer un RNN fragile

## Énoncé

Un RNN fonctionne sur des séquences de longueur 20, mais échoue sur des séquences de longueur 200. Donnez cinq vérifications concrètes.

## Ce que l'exercice vérifie

L'exercice vérifie le diagnostic des modèles séquentiels. Une architecture qui marche sur court contexte peut échouer quand la distance temporelle augmente.

## Solution détaillée

Première vérification : gradients évanescents.

Sur 200 pas, le signal de gradient peut devenir très faible. Le modèle n'apprend pas à utiliser les informations anciennes.

Action :

```text
logger les normes de gradients par couche et par pas
tester LSTM ou GRU
réduire la dépendance longue par features explicites
```

Deuxième vérification : gradients explosifs.

À l'inverse, le gradient peut devenir énorme sur de longues séquences.

Action :

```text
activer gradient clipping
réduire le learning rate
surveiller NaN et Inf
```

Troisième vérification : BPTT tronqué.

Si l'entraînement ne remonte que sur 20 ou 50 pas, le modèle peut échouer sur une dépendance à 150 pas.

Action :

```text
vérifier la longueur de troncature
tester plusieurs fenêtres
comparer coût et performance
```

Quatrième vérification : taille et reset de l'état caché.

L'état caché peut être trop petit pour résumer une séquence longue, ou être remis à zéro au mauvais moment.

Action :

```text
vérifier la gestion de h_0
tester différentes tailles d'état
contrôler les frontières de séquence
```

Cinquième vérification : distribution différente.

Les séquences de longueur 200 ne sont peut-être pas seulement plus longues. Elles peuvent venir d'un autre régime de données.

Action :

```text
comparer statistiques longueur 20 vs 200
vérifier padding et masques
mesurer par sous-groupes
```

Autres pistes :

- normalisation des entrées ;
- initialisation ;
- données trop bruitées ;
- labels dépendant d'un événement rare ;
- architecture simplement inadaptée.

## Points importants

- Longueur 200 teste une dynamique différente de longueur 20.
- Les gradients peuvent disparaître ou exploser.
- Le BPTT tronqué peut masquer le problème.
- Le reset d'état doit être explicite.
- Les masques et le padding sont des sources classiques de bogues.

## Prolongement

Un bon protocole compare un RNN simple, un GRU, un LSTM et une baseline non récurrente. Si la baseline bat le RNN sur longueur 200, ce n'est pas une honte. C'est une information utile.
