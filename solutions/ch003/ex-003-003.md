# EX-003-003 - Mini-batch et bruit de gradient

## Énoncé

Expliquez pourquoi un gradient calculé sur mini-batch peut différer du gradient calculé sur tout le dataset, puis discutez un avantage et un risque.

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre le gradient complet et son estimation stochastique.

Un mini-batch ne voit qu'une partie des données. Il donne donc une approximation du gradient global. Cette approximation peut être utile, mais elle peut aussi être bruitée.

## Solution détaillée

Supposons un dataset complet de `N` exemples. La perte moyenne complète est :

```text
L(theta) = (1/N) * sum_i L_i(theta)
```

Le gradient complet est :

```text
grad L(theta) = (1/N) * sum_i grad L_i(theta)
```

Il utilise tous les exemples.

Avec un mini-batch `B` de taille `m`, on calcule plutôt :

```text
grad L_B(theta) = (1/m) * sum_i_in_B grad L_i(theta)
```

Comme `B` n'est qu'un sous-ensemble, son gradient peut différer du gradient complet. Si le mini-batch contient surtout des exemples faciles, difficiles, rares ou atypiques, la direction estimée peut changer.

Prenons une analogie simple d'ingénierie. Si on veut estimer la charge moyenne d'un service sur une journée complète, regarder seulement cinq minutes de trafic peut être utile, mais pas parfait. Si ces cinq minutes tombent pendant un pic, l'estimation sera trop élevée. Si elles tombent pendant une période calme, elle sera trop basse.

Le mini-batch fonctionne de la même manière : il échantillonne une partie du signal.

### Avantage

Le premier avantage est le coût. Calculer le gradient complet peut être trop lent, surtout avec de grands datasets. Le mini-batch permet de mettre à jour les paramètres plus souvent.

Il a aussi un avantage matériel : les opérations sur batch se parallélisent bien sur GPU. On obtient un bon compromis entre estimation statistique et efficacité de calcul.

Enfin, le bruit du mini-batch peut aider l'optimisation à ne pas suivre une trajectoire trop rigide. Dans certains cas, ce bruit aide à sortir de zones peu intéressantes ou à obtenir une meilleure généralisation.

### Risque

Le risque principal est une estimation trop bruitée. Si la taille de batch est trop petite, les mises à jour peuvent devenir instables. Le modèle avance alors dans des directions très variables.

Autre risque : un échantillonnage mal construit. Si les mini-batches ne représentent pas bien la distribution des données, l'entraînement peut favoriser certains sous-groupes et en négliger d'autres.

Exemples de problèmes :

- batches triés par classe ;
- séries temporelles coupées sans précaution ;
- exemples rares presque jamais vus ;
- données corrélées dans un même batch ;
- distribution train différente de validation.

## Points importants

- Le gradient complet utilise tout le dataset.
- Le gradient mini-batch est une estimation.
- L'estimation varie selon les exemples sélectionnés.
- Le mini-batch réduit le coût et permet une bonne parallélisation.
- Le bruit peut aider, mais trop de bruit rend l'entraînement instable.

## Prolongement

Dans les grands modèles, la taille effective de batch peut être augmentée par accumulation de gradients :

```text
batch physique limité par la mémoire
batch effectif plus grand par accumulation sur plusieurs pas
```

C'est un compromis fréquent quand la mémoire GPU limite le batch réel. Mais là encore, il faut mesurer. Un batch plus grand n'est pas automatiquement meilleur : il peut réduire le bruit utile et modifier la dynamique d'optimisation.
