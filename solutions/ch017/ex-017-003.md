# EX-017-003 - Protocole de comparaison

## Énoncé

Proposez un protocole minimal pour comparer CfC, LTC et GRU.

## Ce que l'exercice vérifie

L'exercice vérifie comment comparer trois familles sans favoriser artificiellement l'une d'elles.

## Solution détaillée

### Modèles à comparer

Comparer au minimum :

```text
GRU
GRU + Delta t
LTC
CfC
```

Le GRU + `Delta t` est important pour donner une baseline discrète informée du temps.

### Données

Utiliser :

- mêmes données ;
- mêmes splits temporels ;
- même normalisation ;
- mêmes masques ;
- mêmes horizons de prédiction.

### Budget

Documenter :

- nombre de paramètres ;
- temps d'entraînement ;
- matériel ;
- batch size ;
- recherche d'hyperparamètres ;
- nombre de seeds.

### Métriques

Mesurer :

- métrique principale de tâche ;
- latence ;
- mémoire ;
- stabilité entre seeds ;
- coût d'entraînement ;
- comportement sur `Delta t` hors distribution ;
- qualité sur séquences longues.

### Tests hors distribution

Créer des variantes :

```text
délais plus longs
valeurs manquantes
bruit ajouté
changement d'amplitude
séquences plus longues
```

## Points importants

- Inclure GRU + `Delta t`.
- Mesurer qualité et coût.
- Tester plusieurs seeds.
- Ajouter des perturbations temporelles.
- Documenter le solveur pour LTC.

## Prolongement

Une comparaison utile ne cherche pas un gagnant universel. Elle cherche le meilleur compromis pour une classe de données et de contraintes.
