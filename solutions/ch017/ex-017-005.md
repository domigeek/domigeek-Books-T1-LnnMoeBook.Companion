# EX-017-005 - CfC dans Qaya

## Énoncé

Décrivez un usage mesurable d'un CfC dans Qaya.

## Ce que l'exercice vérifie

L'exercice vérifie comment présenter une brique temporelle dans une étude de cas sans transformer Qaya en argument marketing.

## Solution détaillée

Un usage mesurable d'un CfC dans Qaya pourrait être le suivi compact d'un état d'orchestration.

Le composant recevrait des événements :

```text
InputReceived
MemoryRetrieved
ExpertInvoked
ExpertFailed
ConstraintApplied
OutputEmitted
```

Chaque événement aurait un `Delta t`, un type, des métadonnées et éventuellement un score.

Le CfC maintiendrait un état latent servant à estimer :

- stabilité du contexte ;
- urgence d'une replanification ;
- besoin de consulter un expert ;
- risque de boucle ;
- effet d'un échec récent ;
- inertie d'une tâche en cours.

Ce composant serait mesuré avec :

```text
latence
qualité de routage
taux de fallback
détection d'épisodes instables
robustesse aux événements fréquents
comparaison avec règles, GRU + Delta t et LTC
```

Il faut éviter de dire que le CfC "comprend" l'orchestration. Il produit un état dynamique utile si les tests le confirment.

## Points importants

- Le CfC peut suivre un état temporel compact.
- Les événements doivent être structurés.
- Les métriques doivent être définies avant l'interprétation.
- Le composant doit être comparé à des baselines.
- Qaya reste une étude de cas architecturale, pas une preuve scientifique.

## Prolongement

Un bon test consisterait à rejouer des scénarios d'orchestration avec bruit, délais et échecs, puis comparer les décisions avec et sans composant CfC.
