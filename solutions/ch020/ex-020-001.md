# EX-020-001 - Choisir une architecture par contrainte

## Énoncé

Pour chaque cas, proposez une architecture de départ et une baseline simple : logs applicatifs longs, chatbot documentaire, série capteur irrégulière, classification tabulaire, modèle local sur téléphone.

## Ce que l'exercice vérifie

L'exercice vérifie une méthode de choix : partir des contraintes et des baselines, pas de la mode du moment.

Une architecture n'est pas bonne dans l'absolu. Elle est adaptée ou non à une tâche, un budget, une latence, une donnée et un contexte d'exploitation.

## Solution détaillée

### Logs applicatifs longs

Architecture de départ :

```text
SSM, GRU ou hybride streaming avec features temporelles
```

Les logs sont longs, continus et souvent orientés détection de changements. Un état compact ou une approche streaming peut être plus efficace qu'une attention dense sur tout l'historique.

Baseline simple :

```text
règles + compteurs temporels + seuils + EWMA
```

### Chatbot documentaire

Architecture de départ :

```text
Transformer + RAG + vérification de sources
```

Le besoin central est de retrouver des documents, sélectionner un contexte et générer une réponse fidèle.

Baseline simple :

```text
recherche lexicale + extrait cité sans génération complexe
```

### Série capteur irrégulière

Architecture de départ :

```text
GRU avec delta_t, Neural ODE simple, LNN ou modèle hybride
```

Le temps irrégulier compte. Il faut éviter de traiter tous les pas comme également espacés si ce n'est pas vrai.

Baseline simple :

```text
interpolation + modèle statistique ou MLP sur fenêtre
```

### Classification tabulaire

Architecture de départ :

```text
MLP ou modèle classique selon la donnée
```

Dans le tabulaire, les arbres de décision boostés ou modèles classiques restent souvent très compétitifs. Un MLP peut être utile, mais il ne faut pas ignorer les baselines fortes.

Baseline simple :

```text
régression logistique, random forest, gradient boosting
```

### Modèle local sur téléphone

Architecture de départ :

```text
modèle compact quantifié, petit Transformer, SSM compact ou modèle spécialisé
```

Les contraintes principales sont mémoire, énergie, latence et taille du binaire.

Baseline simple :

```text
règles, modèle linéaire, petit MLP quantifié
```

## Points importants

- Les logs longs favorisent souvent des états compacts ou du streaming.
- Le documentaire exige récupération, permissions et citations.
- Le temps irrégulier doit être explicitement traité.
- Le tabulaire n'exige pas forcément un réseau profond.
- Le mobile impose des contraintes matérielles strictes.

## Prolongement

Pour chaque choix, il faut définir une métrique de refus. Par exemple : si le modèle local dépasse `x` ms de latence ou `y` Mo de mémoire, il est rejeté même si sa qualité est légèrement meilleure.
