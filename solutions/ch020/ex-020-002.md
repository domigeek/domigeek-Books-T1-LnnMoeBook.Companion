# EX-020-002 - Définir les métriques avant le modèle

## Énoncé

Choisissez une tâche et définissez cinq métriques qui décideront du choix d'architecture.

## Ce que l'exercice vérifie

L'exercice vérifie une discipline : définir comment on jugera avant de choisir ce qu'on construit.

Sans métriques, on finit par préférer l'architecture la plus impressionnante, pas forcément la plus utile.

## Solution détaillée

Prenons une tâche de réponse documentaire en entreprise.

Le système reçoit une question et doit répondre à partir d'un corpus interne autorisé.

### 1. Exactitude supportée par les sources

La réponse doit être correcte selon les documents récupérés.

Mesure possible :

```text
pourcentage de réponses dont les affirmations principales sont supportées par une source
```

### 2. Qualité de citation

Le système doit citer les bons documents, pas seulement produire une réponse plausible.

Mesure possible :

```text
recall@k des documents pertinents
précision des citations
```

### 3. Latence

Un système documentaire peut être excellent mais inutilisable s'il répond trop lentement.

Mesure possible :

```text
p50, p95 et p99 de latence
```

### 4. Coût par requête

Le choix d'architecture dépend du budget.

Mesure possible :

```text
tokens d'entrée
tokens de sortie
coût moyen par requête
coût p95
```

### 5. Respect des permissions

Le système ne doit jamais répondre à partir de documents non autorisés.

Mesure possible :

```text
taux de fuite documentaire sur scénarios de test
```

Ce taux doit idéalement être zéro. Une moyenne agréable ne suffit pas si le système fuit des documents sensibles.

## Points importants

- La qualité seule ne suffit pas.
- Les sources et permissions sont centrales en documentaire.
- La latence doit être mesurée en percentiles.
- Le coût doit être visible.
- Certaines métriques sont des seuils de blocage, pas des moyennes à optimiser.

## Prolongement

Une fois les métriques définies, on peut comparer :

```text
recherche simple
RAG avec petit modèle
RAG avec grand modèle
RAG avec reranker
architecture agentique
```

Sans changer les règles du jeu à chaque essai.
