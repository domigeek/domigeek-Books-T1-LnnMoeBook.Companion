# EX-020-005 - Dette d'hybridation

## Énoncé

Listez cinq formes de dette ajoutées par une architecture hybride LNN + SSM + MoE + mémoire externe.

## Ce que l'exercice vérifie

L'exercice vérifie la lucidité d'architecture. Une hybridation peut être puissante, mais elle ajoute des surfaces de panne, de test et de maintenance.

## Solution détaillée

### 1. Dette de code

Chaque famille de composants a ses abstractions :

```text
dynamique continue
état SSM
routage MoE
mémoire externe
orchestration
```

Le code devient plus difficile à lire, à découper et à faire évoluer.

### 2. Dette de tests

Il faut tester :

- chaque composant seul ;
- les contrats d'entrée/sortie ;
- les interactions ;
- les modes dégradés ;
- les régressions de performance ;
- les cas limites de routage et de mémoire.

### 3. Dette d'observabilité

Un système hybride peut échouer sans planter. Il peut simplement router moins bien, oublier trop vite, récupérer un mauvais document ou produire un état instable.

Il faut donc mesurer :

```text
état
routage
latence
coût
utilisation mémoire
qualité par sous-domaine
erreurs par composant
```

### 4. Dette de versionnement

Chaque brique peut évoluer :

- poids du modèle ;
- experts ;
- index vectoriel ;
- corpus ;
- politique mémoire ;
- prompts ;
- schémas d'événements.

Sans versionnement clair, on ne sait plus pourquoi une réponse a changé.

### 5. Dette de sécurité et gouvernance

La mémoire externe, les outils et le routage ajoutent des frontières de permission.

Il faut gérer :

- droits d'accès ;
- suppression de données ;
- fuite de contexte ;
- audit ;
- politiques de rétention ;
- validation des outils.

### Autres dettes possibles

On peut aussi citer :

- dette de formation d'équipe ;
- dette d'infrastructure ;
- dette de reproductibilité ;
- dette de coûts ;
- dette d'explicabilité ;
- dette de monitoring distribué.

## Points importants

- L'hybridation augmente la surface de maintenance.
- Les tests doivent couvrir les interactions, pas seulement les modules.
- L'observabilité devient centrale.
- Le versionnement est obligatoire pour comprendre les changements.
- La sécurité devient plus complexe avec mémoire et outils.

## Prolongement

Une architecture hybride doit être justifiée par des métriques. Si elle n'améliore pas clairement un compromis important, elle risque de devenir une machine à complexité.
