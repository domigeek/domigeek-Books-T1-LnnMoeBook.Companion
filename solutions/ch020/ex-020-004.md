# EX-020-004 - Baseline obligatoire

## Énoncé

Pour une architecture récente de votre choix, proposez deux baselines simples à battre.

## Ce que l'exercice vérifie

L'exercice vérifie une règle saine : une architecture récente doit battre des baselines crédibles, pas seulement produire un résultat séduisant isolé.

## Solution détaillée

Prenons une architecture hybride pour logs applicatifs :

```text
SSM + routeur MoE + mémoire d'incidents
```

Elle vise à détecter des anomalies dans un flux de logs et à proposer une explication opérationnelle.

### Baseline 1 : règles et compteurs temporels

Première baseline :

```text
seuils sur taux d'erreur, latence p95, retries, saturation CPU/mémoire
```

Pourquoi cette baseline ?

Parce qu'en monitoring, les règles simples sont souvent très fortes. Elles sont lisibles, rapides, robustes et faciles à maintenir.

Le modèle hybride doit battre cette baseline sur une métrique utile, par exemple :

```text
rappel incidents critiques
faux positifs par jour
délai de détection
```

### Baseline 2 : GRU ou SSM simple

Deuxième baseline :

```text
modèle séquentiel unique sans MoE ni mémoire externe
```

Pourquoi ?

Parce qu'il faut savoir si l'hybridation apporte vraiment quelque chose. Si un modèle séquentiel simple atteint la même performance avec moins de complexité, l'architecture hybride n'est pas justifiée.

### Protocole comparable

Les trois systèmes doivent partager :

- même découpage temporel ;
- même définition d'incident ;
- mêmes métriques ;
- même fenêtre d'observation ;
- même budget de latence si possible ;
- même jeu de test final.

Il faut aussi mesurer le coût :

```text
temps d'entraînement
latence d'inférence
mémoire
charge opérationnelle
complexité de déploiement
```

## Points importants

- Une baseline simple peut être très forte.
- Une architecture récente doit justifier sa complexité.
- Les métriques doivent être définies avant la comparaison.
- Le protocole doit être comparable.
- Battre la baseline en qualité ne suffit pas si le coût explose.

## Prolongement

Une bonne conclusion pourrait être :

```text
L'hybride améliore le rappel critique de 8 points, mais double la latence et demande plus de monitoring. Il est pertinent seulement pour les services critiques.
```

C'est plus utile qu'un verdict abstrait comme "l'hybride est meilleur".
