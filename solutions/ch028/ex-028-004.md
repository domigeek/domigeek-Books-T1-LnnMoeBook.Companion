# EX-028-004 - Routage limité par device

## Énoncé

Expliquez pourquoi un routage top-k non contraint peut être inefficace si les experts sont répartis sur plusieurs devices.

## Ce que l'exercice vérifie

L'exercice vérifie la relation entre routage modèle et communication matérielle.

## Solution détaillée

Dans un top-k non contraint, le routeur choisit les meilleurs experts selon les scores, peu importe leur emplacement matériel.

Si les experts sont répartis sur plusieurs devices, un token peut devoir aller chercher ses experts sur plusieurs GPUs ou machines.

Conséquences :

- communication all-to-all ;
- latence plus élevée ;
- bande passante saturée ;
- recombinaison plus coûteuse ;
- synchronisation plus complexe ;
- débit global réduit.

Exemple :

```text
token sur device 0
expert choisi 1 sur device 2
expert choisi 2 sur device 5
```

Le calcul expert est sparse, mais le mouvement de données devient cher.

Un routage limité par device peut réduire ce coût en favorisant des experts proches ou en limitant le nombre de devices impliqués par token.

Le risque est de réduire la liberté du routeur. Il faut donc mesurer le compromis :

```text
moins de communication
contre
potentielle baisse de qualité
```

## Points importants

- Top-k non contraint peut déclencher beaucoup de communication.
- Le placement des experts compte.
- L'all-to-all peut dominer la latence.
- Limiter les devices candidats peut améliorer l'efficacité.
- La contrainte matérielle doit être évaluée contre la qualité.

## Prolongement

Un routeur moderne doit parfois être conscient de l'infrastructure. Le meilleur expert abstrait n'est pas toujours le meilleur choix système.
