# EX-028-001 - Experts partagés dans un MoE simple

## Énoncé

Modifiez un MoE simple pour ajouter un expert partagé toujours actif et plusieurs experts routés sélectionnés par top-k.

## Ce que l'exercice vérifie

L'exercice vérifie le principe experts partagés plus experts routés : une base commune et une capacité spécialisée.

## Solution détaillée

Une formulation simple :

```text
shared = SharedExpert(x)
routed = 0

indices, weights = TopKRouter(x)

for each selected expert i:
    routed += weights[i] * Expert_i(x)

output = x + shared + routed
```

Le terme `shared` est toujours actif. Il capture une transformation commune.

Le terme `routed` dépend des experts sélectionnés par le routeur.

La connexion résiduelle `x + ...` est optionnelle selon l'architecture, mais elle aide souvent à préserver le signal.

Tests utiles :

- l'expert partagé est appelé pour tous les tokens ;
- seuls les experts top-k routés sont appelés ;
- les poids routés somment à `1` ;
- la sortie garde la shape d'entrée attendue ;
- retirer l'expert partagé modifie bien la sortie.

## Points importants

- L'expert partagé fournit une capacité commune.
- Les experts routés fournissent une capacité conditionnelle.
- Le coût actif augmente avec l'expert partagé.
- La sortie combine shared, routed et éventuellement résiduel.
- Il faut faire des ablations.

## Prolongement

Un expert partagé trop puissant peut rendre les experts routés moins utiles. Sa taille et son rôle doivent être mesurés.
