# EX-024-001 - Dispatch sparse minimal

## Énoncé

Décrivez ou implémentez un dispatch sparse minimal pour une couche MoE.

## Ce que l'exercice vérifie

L'exercice vérifie la mécanique concrète d'une couche sparse : sélectionner, regrouper, exécuter, recomposer.

## Solution détaillée

Un dispatch sparse minimal suit quatre étapes.

### 1. Router les tokens

Pour chaque token, le routeur produit des logits par expert. On applique top-k :

```text
indices, poids = top_k(router(token))
```

### 2. Regrouper par expert

On crée des lots par expert :

```text
expert 0 -> tokens [0, 4, 8]
expert 1 -> tokens [2, 7]
expert 2 -> tokens [1, 3, 5]
```

Chaque expert ne reçoit que les tokens qui lui sont assignés.

### 3. Exécuter les experts actifs

On applique chaque expert à son sous-batch :

```text
output_e = expert_e(tokens_e)
```

### 4. Recomposer dans l'ordre original

Pour chaque token, on remet les sorties au bon emplacement et on applique les poids de routage :

```text
y_token = somme_j poids_j * sortie_expert_j
```

Il faut préserver l'ordre original du batch. Sinon, le modèle peut produire des sorties associées aux mauvais tokens.

## Points importants

- Le dispatch commence par top-k.
- Les tokens sont groupés par expert.
- Seuls les experts actifs sont exécutés.
- Les sorties doivent être recomposées dans l'ordre initial.
- Les poids doivent être appliqués correctement.

## Prolongement

Dans un vrai système, il faut ajouter capacité par expert, tokens débordés, communication entre devices, buffers et métriques de routage.
