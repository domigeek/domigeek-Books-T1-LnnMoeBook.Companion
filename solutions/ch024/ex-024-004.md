# EX-024-004 - Choix de k

## Énoncé

Comparez une couche MoE sparse avec `k = 1` et une autre avec `k = 2`.

## Ce que l'exercice vérifie

L'exercice vérifie le compromis entre simplicité, coût actif et coopération d'experts.

## Solution détaillée

Avec `k = 1`, chaque token active un seul expert.

Avantages :

- coût actif plus faible ;
- dispatch plus simple ;
- recombinaison minimale ;
- latence potentiellement plus basse ;
- logique proche de Switch Transformer.

Risques :

- mauvais routage plus coûteux ;
- pas de coopération entre experts pour un token ;
- expert unique trop chargé ;
- besoin fort de load balancing.

Avec `k = 2`, chaque token active deux experts.

Avantages :

- plus de flexibilité ;
- possibilité de combiner compétences ;
- meilleure tolérance à un routage imparfait ;
- transition plus douce entre experts.

Risques :

- coût actif environ doublé côté experts ;
- recombinaison plus complexe ;
- communication plus élevée ;
- latence potentiellement plus grande ;
- load balancing plus délicat.

Le choix dépend de la tâche et de l'infrastructure. `k = 1` n'est pas automatiquement meilleur. `k = 2` n'est pas automatiquement plus intelligent. Ce sont deux compromis.

## Points importants

- `k = 1` privilégie simplicité et coût.
- `k = 2` privilégie flexibilité et coopération.
- Le top-1 est plus sensible au mauvais routage.
- Le top-2 coûte plus cher.
- Le choix doit être mesuré.

## Prolongement

Switch illustre la force du top-1. Mixtral illustre un compromis top-2. Les deux existent parce que le bon choix dépend du contexte.
