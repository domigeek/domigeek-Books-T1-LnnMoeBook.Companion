# EX-005-004 - Limite d'architecture

## Énoncé

Décrivez un cas métier où une règle linéaire simple pourrait être suffisante, puis un cas où elle serait probablement insuffisante.

## Ce que l'exercice vérifie

L'exercice vérifie une compétence d'architecte : choisir la complexité minimale utile. Un modèle simple n'est pas honteux. Il devient un problème seulement quand le phénomène à modéliser exige plus que ce qu'il peut représenter.

## Solution détaillée

Un cas où une règle linéaire peut suffire : prioriser des tickets de support selon quelques signaux très clairs.

Par exemple :

```text
score = 3*client_premium + 2*incident_production + 1*nombre_utilisateurs_affectes - 1*age_ticket
```

Ce n'est pas forcément un modèle ML sophistiqué. Mais si le but est de trier grossièrement des tickets selon une politique métier explicite, une combinaison linéaire peut être robuste, compréhensible et facile à auditer.

Elle est suffisante si :

- les facteurs s'additionnent à peu près indépendamment ;
- les seuils de décision sont simples ;
- les interactions entre variables sont faibles ;
- l'objectif est une priorisation approximative ;
- la transparence est plus importante que la finesse.

Un cas où une règle linéaire serait insuffisante : détecter une fraude transactionnelle complexe.

Dans ce type de problème, le signal peut dépendre d'interactions :

- montant inhabituel seulement pour ce client ;
- pays inhabituel seulement à certaines heures ;
- appareil nouveau mais comportement normal ;
- petite transaction suivie d'une grosse transaction ;
- séquence d'actions qui a du sens seulement dans l'ordre.

Une règle linéaire peut additionner des facteurs, mais elle représente mal les combinaisons conditionnelles et les dynamiques temporelles. Elle peut dire "ce facteur augmente le risque", mais elle a du mal à exprimer "ce facteur augmente le risque seulement quand deux autres conditions sont réunies".

Dans ce deuxième cas, on pourrait avoir besoin :

- de features d'interaction ;
- d'un MLP ;
- d'un modèle séquentiel ;
- d'un système de règles combiné à un modèle ;
- d'une mémoire ou d'une agrégation temporelle.

## Points importants

- Une règle linéaire est utile quand les effets sont approximativement additifs.
- Elle est lisible et facile à déboguer.
- Elle devient limitée quand le problème dépend d'interactions, de seuils multiples ou de séquences.
- Le bon choix dépend de la tâche, du coût de l'erreur et du besoin d'explication.

## Prolongement

Avant d'augmenter la complexité, il faut mesurer une baseline linéaire. Si un modèle complexe ne bat pas clairement une baseline simple sur des métriques pertinentes, il apporte peut-être surtout du coût et de l'opacité.
