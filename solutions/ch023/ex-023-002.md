# EX-023-002 - Effondrement contrôlé

## Énoncé

Créez un cas contrôlé où un routeur envoie presque toutes les entrées vers le même expert.

## Ce que l'exercice vérifie

L'exercice vérifie le phénomène d'expert collapse. Un routeur peut apprendre ou produire une distribution très déséquilibrée.

## Solution détaillée

On peut créer un cas simple avec quatre experts et des logits biaisés :

```text
token 0 : [10, 1, 0, 0]
token 1 : [9,  2, 0, 0]
token 2 : [11, 0, 1, 0]
token 3 : [8,  0, 0, 2]
token 4 : [12, 1, 1, 1]
```

Avec top-1, l'expert `0` sera sélectionné pour presque tous les tokens.

Histogramme attendu :

```text
expert 0 : 5
expert 1 : 0
expert 2 : 0
expert 3 : 0
```

Ce collapse peut apparaître parce que :

- le routeur favorise trop un expert ;
- les données sont déséquilibrées ;
- l'initialisation crée une préférence ;
- un expert apprend plus vite et attire encore plus de tokens ;
- la loss de load balancing est absente ou trop faible.

Mitigations possibles :

- loss auxiliaire d'équilibrage ;
- bruit de routage pendant l'entraînement ;
- capacité par expert ;
- pénalité d'entropie ;
- meilleure initialisation ;
- monitoring des usages par expert ;
- drop ou reroutage des tokens débordés.

## Points importants

- Le collapse réduit l'utilité de la capacité totale.
- Un histogramme d'utilisation est le premier diagnostic.
- L'équilibrage doit prévenir la surcharge sans forcer une uniformité artificielle.
- Les mitigations doivent être testées contre la qualité de tâche.

## Prolongement

Dans un système réel, il faut surveiller l'évolution du collapse dans le temps. Un routeur équilibré au début peut se dégrader pendant l'entraînement.
