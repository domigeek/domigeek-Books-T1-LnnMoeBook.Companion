# EX-023-001 - Tester top-k

## Énoncé

Écrivez un petit test conceptuel pour un routeur top-k avec `k = 1`, `k = 2` et `k = 4`.

## Ce que l'exercice vérifie

L'exercice vérifie qu'un routeur top-k doit être testé sur ses indices, ses poids et ses shapes. Un routeur qui "semble marcher" peut cacher une mauvaise renormalisation.

## Solution détaillée

On peut utiliser une matrice de logits simple :

```text
logits =
token 0 : [4.0, 1.0, 0.0, 2.0]
token 1 : [0.1, 3.0, 2.0, 1.0]
```

Pour `k = 1`, on attend :

```text
token 0 -> expert 0
token 1 -> expert 1
```

Il faut vérifier :

- un seul expert actif par token ;
- shape des indices `(tokens, 1)` ;
- shape des poids `(tokens, 1)` ;
- poids égal à `1` après renormalisation sur les experts gardés.

Pour `k = 2`, on attend :

```text
token 0 -> experts 0 et 3
token 1 -> experts 1 et 2
```

Il faut vérifier que les poids softmax sont recalculés seulement sur les deux logits retenus.

Pour `k = 4`, tous les experts sont retenus. Le comportement doit revenir à une combinaison dense sur les quatre experts.

Pseudo-test :

```text
result = TopKRouter(logits, k)
assert result.indices.shape == (tokens, k)
assert result.weights.shape == (tokens, k)
assert sum(result.weights[token]) == 1
assert no duplicated expert per token
assert selected indices match expected top-k
```

## Points importants

- Tester `k = 1`, `k = 2` et `k = nombre_experts`.
- Vérifier les shapes.
- Vérifier la somme des poids.
- Vérifier les indices attendus.
- Vérifier qu'un expert non retenu a un poids nul dans la matrice sparse finale.
