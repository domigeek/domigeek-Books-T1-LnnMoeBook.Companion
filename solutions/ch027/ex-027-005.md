# EX-027-005 - Déploiement réaliste

## Énoncé

Listez les métriques à surveiller pour servir un modèle MoE top-2 dans une application interactive.

## Ce que l'exercice vérifie

L'exercice vérifie l'observabilité nécessaire à l'inférence interactive d'un MoE.

## Solution détaillée

Métriques principales :

- latence p50, p95, p99 ;
- throughput en tokens par seconde ;
- batch size effectif ;
- utilisation GPU ;
- mémoire utilisée ;
- KV cache ;
- tokens par expert ;
- charge par device ;
- taux de tokens débordés ;
- latence de dispatch ;
- temps de recombinaison ;
- erreurs d'inférence ;
- coût par requête ;
- qualité applicative.

Pour du top-2, il faut aussi surveiller :

```text
nombre moyen d'experts appelés
distribution des poids top-2
déséquilibre entre premier et second expert
```

Une application interactive a des contraintes fortes. Une bonne moyenne ne suffit pas si le p99 est mauvais.

Il faut aussi suivre les dérives :

- changement de distribution d'entrées ;
- experts qui deviennent dominants ;
- latence qui augmente après changement de trafic ;
- qualité qui baisse sur certains sous-domaines.

## Points importants

- Mesurer les percentiles de latence.
- Suivre tokens par expert et charge par device.
- Surveiller mémoire et KV cache.
- Mesurer coût par requête.
- Relier métriques système et qualité applicative.

## Prolongement

Un MoE top-2 peut être très efficace, mais il demande une exploitation sérieuse. Sans métriques, il est difficile de savoir si la sparsité aide ou complique.
