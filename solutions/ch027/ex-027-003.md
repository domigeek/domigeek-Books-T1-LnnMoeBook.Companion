# EX-027-003 - Paramètres actifs et mémoire

## Énoncé

Expliquez pourquoi un modèle avec environ `13B` paramètres actifs par token peut tout de même exiger une mémoire liée à environ `47B` paramètres.

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre calcul actif et stockage nécessaire.

## Solution détaillée

Dans un MoE, tous les experts ne sont pas utilisés pour chaque token. Par exemple, le modèle peut activer seulement deux experts par token.

Cela donne un nombre de paramètres actifs inférieur au nombre total de paramètres.

Mais pour servir le modèle, il faut que les paramètres non actifs soient disponibles en mémoire ou accessibles rapidement.

Donc :

```text
paramètres actifs par token != paramètres à stocker
```

Un modèle peut utiliser environ `13B` paramètres pour calculer un token, mais contenir environ `47B` paramètres au total.

La mémoire doit aussi inclure :

- experts non activés ;
- couches partagées ;
- embeddings ;
- attention ;
- KV cache ;
- buffers ;
- runtime ;
- quantification éventuelle ;
- overhead de placement.

Le calcul actif influence les FLOPs par token. La mémoire totale influence le chargement, le déploiement et la capacité du matériel.

## Points importants

- Paramètres actifs et paramètres stockés sont différents.
- Les experts non actifs doivent quand même être disponibles.
- Le KV cache ajoute un coût en inférence.
- La bande passante mémoire compte.
- Un MoE peut être sparse en calcul mais lourd en mémoire.

## Prolongement

Pour déployer un MoE, il faut mesurer latence, mémoire, débit et placement, pas seulement le nombre de paramètres actifs annoncé.
