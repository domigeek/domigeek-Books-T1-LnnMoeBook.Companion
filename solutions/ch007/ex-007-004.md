# EX-007-004 - Mini-batch

## Énoncé

Expliquez pourquoi un mini-batch est à la fois un compromis statistique et un compromis matériel.

## Ce que l'exercice vérifie

L'exercice vérifie une idée très pratique : la taille de batch n'est pas seulement un hyperparamètre mathématique. Elle est aussi contrainte par la machine.

## Solution détaillée

Statistiquement, un mini-batch est un échantillon du dataset.

Au lieu de calculer le gradient sur toutes les données, on estime le gradient sur un sous-ensemble :

```text
gradient mini-batch ≈ gradient dataset complet
```

Plus le batch est petit, plus l'estimation peut être bruitée. Plus il est grand, plus l'estimation est stable, mais moins on fait de mises à jour par passage complet sur les données.

Le compromis statistique est donc :

```text
petit batch : plus de bruit, mises à jour fréquentes
grand batch : moins de bruit, coût plus élevé par mise à jour
```

Matériellement, le mini-batch permet de paralléliser les calculs.

Un GPU est efficace quand il travaille sur des blocs de données. Calculer une couche pour 128 exemples en parallèle peut être beaucoup plus rentable que traiter un exemple à la fois.

Mais un batch plus grand consomme plus de mémoire :

- activations du forward ;
- gradients ;
- buffers temporaires ;
- états de l'optimiseur ;
- éventuels caches.

Le compromis matériel est donc :

```text
batch trop petit : mauvaise utilisation du GPU
batch trop grand : mémoire saturée
```

Il faut aussi distinguer batch physique et batch effectif. Avec accumulation de gradients, on peut traiter plusieurs petits batches avant de faire une mise à jour. Cela simule un batch plus grand sans tout mettre en mémoire en même temps.

## Points importants

- Le mini-batch estime le gradient global.
- La taille du batch influence le bruit d'optimisation.
- Le batch est aussi une unité de parallélisation.
- La mémoire limite souvent le batch physique.
- L'accumulation de gradients peut augmenter le batch effectif.

## Prolongement

Changer la taille de batch peut demander de retoucher le learning rate. Ce n'est pas un paramètre isolé. En entraînement réel, batch size, learning rate, scheduler, mémoire et stabilité forment un petit système couplé.
