# EX-007-003 - Diagnostiquer un entraînement instable

## Énoncé

La loss devient NaN après quelques centaines d'itérations. Donnez cinq vérifications concrètes.

## Ce que l'exercice vérifie

L'exercice vérifie le diagnostic pratique. Une loss `NaN` n'est pas une explication. C'est une alarme. Il faut remonter les causes possibles.

## Solution détaillée

Première vérification : le learning rate.

Un taux d'apprentissage trop élevé peut faire exploser les poids ou les activations. Le modèle saute hors d'une zone numérique raisonnable, puis une opération produit `Inf` ou `NaN`.

Action :

```text
réduire le learning rate
tester un warmup
observer la norme des gradients
```

Deuxième vérification : les gradients explosifs.

Si la norme des gradients devient énorme, les mises à jour peuvent rendre les paramètres instables.

Action :

```text
logger gradient_norm
ajouter du gradient clipping
inspecter la couche où l'explosion commence
```

Troisième vérification : les données.

Les entrées ou labels peuvent déjà contenir `NaN`, `Inf` ou des valeurs extrêmes.

Action :

```text
scanner le dataset
vérifier normalisation et standardisation
logger min, max, moyenne, écart-type
```

Quatrième vérification : la formulation de la loss.

Certaines opérations sont fragiles :

```text
log(0)
division par zéro
sqrt(valeur négative)
softmax naïf sur très grands logits
```

Action :

```text
utiliser des fonctions stables du framework
ajouter epsilon si nécessaire
éviter softmax + log à la main si cross-entropy existe
```

Cinquième vérification : dtype et précision.

En float16 ou mixed precision, certaines valeurs peuvent déborder plus facilement.

Action :

```text
tester en float32
vérifier loss scaling
surveiller les activations
```

Autres vérifications utiles :

- initialisation des poids ;
- batch trop petit ou très bruité ;
- labels hors plage ;
- masques incorrects ;
- opérations inplace qui cassent l'autograd.

## Points importants

- Une loss `NaN` doit être localisée.
- Le learning rate est souvent le premier suspect.
- Les données doivent être vérifiées avant l'entraînement.
- Les opérations numériques fragiles doivent utiliser des versions stables.
- Logger les normes de gradients et d'activations fait gagner beaucoup de temps.

## Prolongement

Une bonne boucle d'entraînement devrait pouvoir s'arrêter proprement dès qu'un `NaN` apparaît, enregistrer le batch fautif, les métriques numériques et le checkpoint précédent. Sinon, on débogue dans le brouillard.
