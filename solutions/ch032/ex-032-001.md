# EX-032-001 - Transformer une liste de concepts en graphe relationnel

## Énoncé

Prenez une liste de dix concepts liés à ce livre : LNN, MoE, RAG, mémoire persistante, embedding, graphe, routage, expert, oubli contrôlé, observabilité.

## Ce que l'exercice vérifie

L'exercice vérifie le passage d'une liste plate à une représentation relationnelle. Un concept isolé est moins utile qu'un concept relié.

## Solution détaillée

Graphe possible :

```text
LNN -> maintient -> état temporel
MoE -> utilise -> routage
routage -> sélectionne -> expert
RAG -> consulte -> mémoire persistante
mémoire persistante -> exige -> oubli contrôlé
embedding -> représente -> similarité
graphe -> représente -> relations explicites
observabilité -> mesure -> routage
observabilité -> mesure -> mémoire persistante
expert -> appartient à -> MoE
```

On peut organiser les relations en catégories :

| Source | Relation | Cible |
|---|---|---|
| MoE | sélectionne | expert |
| routage | produit | scores |
| RAG | récupère depuis | mémoire persistante |
| embedding | encode | proximité vectorielle |
| graphe | encode | relations nommées |
| oubli contrôlé | gouverne | mémoire persistante |
| observabilité | audite | routage |
| LNN | modélise | dynamique temporelle |

Le graphe rend visibles les dépendances. Par exemple, une mémoire persistante sans oubli contrôlé devient risquée. Un routage sans observabilité devient difficile à exploiter.

## Points importants

- Une liste de concepts ne suffit pas.
- Les relations doivent être nommées.
- Embedding et graphe ne représentent pas la même chose.
- L'observabilité relie architecture et exploitation.
- Les relations peuvent être versionnées.

## Prolongement

Un graphe conceptuel utile doit accepter les corrections. Si une relation est trop vague, il faut pouvoir la remplacer par une relation plus précise.
