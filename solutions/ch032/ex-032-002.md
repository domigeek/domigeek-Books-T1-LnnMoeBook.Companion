# EX-032-002 - Nommer quatre limites des représentations vectorielles

## Énoncé

Expliquez quatre limites des embeddings dans un système de mémoire conceptuelle.

## Ce que l'exercice vérifie

L'exercice vérifie que les embeddings sont utiles, mais pas suffisants pour représenter toute la connaissance d'un système.

## Solution détaillée

### 1. Relations implicites

Un embedding encode une proximité dans un espace vectoriel, mais il ne dit pas forcément quelle relation existe.

Deux concepts peuvent être proches parce qu'ils sont synonymes, opposés, souvent co-occurrents ou simplement présents dans le même domaine.

### 2. Difficulté d'audit

Un vecteur n'explique pas facilement pourquoi une récupération a eu lieu. Pour un système critique, il faut souvent une provenance, une source et une relation explicite.

### 3. Confusion de contexte

Un mot comme "modèle" peut désigner un modèle ML, un modèle économique, un modèle de données ou un modèle mental. Un embedding peut mélanger les contextes si la représentation n'est pas assez contextualisée.

### 4. Mise à jour et correction

Corriger une connaissance dans un espace vectoriel n'est pas aussi simple que modifier une fiche ou une relation dans un graphe. La mémoire vectorielle doit souvent être réindexée ou enrichie par métadonnées.

Autres limites :

- gestion du temps ;
- permissions ;
- négation ;
- causalité ;
- versionnement ;
- oubli contrôlé.

## Points importants

- La proximité vectorielle n'est pas une relation nommée.
- Les embeddings sont difficiles à auditer seuls.
- Le contexte change le sens.
- Les corrections exigent une gouvernance.
- Les graphes et métadonnées complètent les vecteurs.

## Prolongement

Un bon système de mémoire combine souvent embeddings pour retrouver vite et graphes ou fiches structurées pour expliquer, gouverner et corriger.
