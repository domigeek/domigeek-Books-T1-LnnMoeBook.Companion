# EX-032-005 - Comparer embedding et graphe pour une même tâche

## Énoncé

Choisissez une tâche de retrieval sur un corpus technique.

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre recherche par similarité vectorielle et recherche par relations explicites.

## Solution détaillée

Tâche : retrouver des documents utiles pour diagnostiquer une erreur `HTTP 429` dans une API.

### Embedding

On encode la requête :

```text
"Pourquoi mon API retourne 429 ?"
```

Puis on cherche les chunks vectoriellement proches.

Avantages :

- retrouve des formulations proches ;
- tolère synonymes et paraphrases ;
- rapide avec un index vectoriel.

Limites :

- peut récupérer des documents vagues ;
- ne connaît pas forcément la fraîcheur ;
- ne garantit pas une relation causale ;
- dépend du chunking.

### Graphe

On utilise des relations explicites :

```text
HTTP 429 -> signifie -> rate limit
rate limit -> mitigé par -> backoff
rate limit -> configuré par -> quota
```

Avantages :

- relations lisibles ;
- meilleur audit ;
- navigation explicite ;
- règles de fraîcheur et permissions plus faciles.

Limites :

- construction plus coûteuse ;
- couverture incomplète ;
- maintenance nécessaire.

### Hybride

Le plus robuste est souvent :

```text
embedding pour trouver des candidats
graphe/métadonnées pour filtrer et expliquer
```

## Points importants

- L'embedding récupère par proximité.
- Le graphe récupère par relation.
- Les deux répondent à des questions différentes.
- Un système technique gagne souvent à les combiner.
- Les métadonnées de fraîcheur et permission sont indispensables.

## Prolongement

Un bon retrieval ne cherche pas seulement le texte le plus proche. Il cherche le document utile, autorisé, récent et supportant réellement la réponse.
