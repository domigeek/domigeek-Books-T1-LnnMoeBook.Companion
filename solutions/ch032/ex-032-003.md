# EX-032-003 - Désambiguïser un concept selon le contexte

## Énoncé

Prenez le mot "port" ou "modèle". Produisez trois contextes différents et expliquez comment la représentation devrait changer.

## Ce que l'exercice vérifie

L'exercice vérifie que le sens d'un concept dépend du contexte. Une mémoire conceptuelle doit éviter de fusionner des homonymes ou usages trop différents.

## Solution détaillée

Prenons le mot "port".

### Contexte réseau

```text
Le service écoute sur le port 443.
```

Ici, "port" désigne un port réseau. Relations utiles :

- appartient à un protocole ;
- associé à une socket ;
- exposé par un service ;
- soumis à firewall.

### Contexte maritime

```text
Le navire arrive au port de Montréal.
```

Ici, "port" désigne une infrastructure physique. Relations :

- localisé dans une ville ;
- reçoit des navires ;
- gère du fret ;
- dépend d'une autorité portuaire.

### Contexte logiciel

```text
Nous devons faire le port de cette librairie vers Linux.
```

Ici, "port" désigne une adaptation logicielle. Relations :

- source platform ;
- target platform ;
- compatibilité ;
- dépendances ;
- tests.

Une représentation robuste devrait créer des entrées distinctes ou des sens contextualisés :

```text
port_network
port_maritime
port_software_porting
```

## Points importants

- Le même mot peut désigner plusieurs concepts.
- Le contexte détermine les relations pertinentes.
- Une mémoire doit éviter les collisions de sens.
- Les embeddings contextualisés aident, mais les relations explicites restent utiles.
- Les fiches conceptuelles peuvent être versionnées.

## Prolongement

Dans un RAG technique, la désambiguïsation évite de récupérer des documents réseau quand l'utilisateur parle de portage logiciel.
