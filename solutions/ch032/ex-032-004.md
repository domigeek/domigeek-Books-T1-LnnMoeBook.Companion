# EX-032-004 - Versionner une fiche conceptuelle

## Énoncé

Créez une fiche conceptuelle pour "robustesse" avec deux versions : une version vague et une version corrigée avec métriques, contexte et sources.

## Ce que l'exercice vérifie

L'exercice vérifie qu'un concept technique doit être stabilisé par contexte, métriques et limites.

## Solution détaillée

### Version vague

```text
Concept : robustesse
Définition : capacité d'un modèle à bien fonctionner même quand les données changent.
```

Problème : cette définition est trop vague. Elle ne dit pas quelles données changent, quelle métrique baisse, ni dans quelles conditions.

### Version corrigée

```text
Concept : robustesse
Version : 2
Contexte : séries temporelles irrégulières de monitoring applicatif
Définition : capacité d'un modèle à maintenir une performance acceptable quand les entrées subissent des perturbations réalistes.
Perturbations : bruit, valeurs manquantes, délais variables, burst d'événements.
Métriques : F1 incident, rappel critique, latence p95, taux de faux positifs.
Seuil : baisse de F1 inférieure à 5 % sur scénarios de bruit modéré.
Sources : protocole expérimental interne, chapitre LNN, benchmark de validation.
Limites : ne couvre pas tous les changements de domaine.
```

La version corrigée rend le concept testable. On peut encore discuter le seuil, mais au moins on sait de quoi on parle.

## Points importants

- Une définition vague est difficile à tester.
- Le contexte est obligatoire.
- Les métriques rendent le concept opérationnel.
- Les sources donnent la provenance.
- Les limites évitent la survente.

## Prolongement

Une mémoire conceptuelle sérieuse doit garder les versions. Sinon, le système peut réutiliser une ancienne définition trop vague sans que personne ne le voie.
