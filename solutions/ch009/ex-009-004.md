# EX-009-004 - Coût architectural

## Énoncé

Pourquoi un LSTM est-il plus coûteux qu'un RNN simple ?

## Ce que l'exercice vérifie

L'exercice vérifie le coût réel des portes. Les LSTM améliorent le contrôle de l'information, mais ils paient cette capacité par plus de calcul, plus de paramètres et plus d'activations.

## Solution détaillée

Un RNN simple calcule essentiellement :

```text
h_t = tanh(W_x*x_t + W_h*h_{t-1} + b)
```

Il y a une transformation pour l'entrée, une transformation pour l'état précédent, un biais et une activation.

Un LSTM calcule plusieurs composantes :

```text
f_t : porte d'oubli
i_t : porte d'entrée
g_t : contenu candidat
o_t : porte de sortie
```

Chaque composante nécessite des poids, des biais et des activations. En pratique, on regroupe souvent ces calculs dans une grande matrice pour l'efficacité, mais le coût logique reste plus élevé.

Le LSTM doit aussi maintenir deux états :

```text
c_t : cell state
h_t : hidden state
```

Cela augmente :

- le nombre de paramètres ;
- le nombre d'opérations par pas ;
- la mémoire nécessaire pour stocker les activations pendant l'entraînement ;
- la complexité de l'implémentation ;
- le coût de backpropagation through time.

Ce coût peut être justifié si la tâche bénéficie du contrôle offert par les portes. Mais si une tâche est simple ou courte, un RNN simple, un GRU ou même un MLP sur fenêtres peut suffire.

## Points importants

- Le LSTM calcule plusieurs portes.
- Il maintient `c_t` et `h_t`.
- Il utilise plus de paramètres qu'un RNN simple comparable.
- Il consomme plus de mémoire pendant l'entraînement.
- Ce coût est un compromis contre une meilleure gestion de certaines dépendances temporelles.

## Prolongement

Le GRU est souvent présenté comme une alternative plus compacte. Il garde l'idée de portes, mais avec une structure plus simple et un seul état principal.
