# EX-009-005 - Limite de la mémoire LSTM

## Énoncé

Expliquez pourquoi un LSTM ne remplace pas une mémoire persistante ou un système RAG.

## Ce que l'exercice vérifie

L'exercice vérifie une distinction importante : mémoire latente de modèle et mémoire externe vérifiable ne jouent pas le même rôle.

## Solution détaillée

Un LSTM maintient un état interne pendant le traitement d'une séquence :

```text
c_t
h_t
```

Cet état aide le modèle à transporter de l'information utile pour la tâche. Mais il est :

- latent ;
- compressé ;
- dépendant de la séquence courante ;
- non directement consultable ;
- difficile à auditer ;
- perdu ou réinitialisé selon le contexte d'exécution.

Une mémoire persistante ou un système RAG répond à un autre besoin. Il permet de stocker, retrouver et citer des informations externes :

```text
documents
faits
épisodes
versions
sources
horodatages
```

Un système RAG peut dire : "cette réponse vient de tel document". Un LSTM ne peut pas fournir ce genre de traçabilité à partir de son état interne.

Le LSTM peut retenir une tendance dans une séquence. Il ne remplace pas :

- une base documentaire ;
- un vector store ;
- un graphe de connaissances ;
- une politique de mise à jour mémoire ;
- un mécanisme de suppression ou d'audit.

La confusion vient du mot "mémoire". Dans les deux cas, on parle de conserver de l'information, mais pas avec les mêmes garanties.

## Points importants

- L'état LSTM est latent, pas documentaire.
- Il n'est pas directement consultable ni vérifiable.
- Il dépend du contexte courant.
- Un RAG récupère des sources externes.
- Pour une architecture sérieuse, mémoire latente et mémoire persistante sont complémentaires.

## Prolongement

Dans une architecture modulaire, un LSTM ou un LNN peut aider à suivre une dynamique. Une mémoire externe peut stocker des connaissances et des épisodes. Les deux ne doivent pas être confondus.
