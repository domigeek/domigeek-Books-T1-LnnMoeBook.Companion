# EX-016-003 - Stabilité

## Énoncé

Donnez trois sens différents du mot "stabilité" dans le contexte d'un LTC.

## Ce que l'exercice vérifie

L'exercice vérifie que le mot "stabilité" est ambigu. Dans les réseaux continus, il peut désigner plusieurs choses différentes. Les mélanger crée des affirmations floues.

## Solution détaillée

### 1. Stabilité mathématique

On peut parler de stabilité de la dynamique : si l'état est légèrement perturbé, revient-il vers une trajectoire ou un attracteur, ou diverge-t-il ?

Cela concerne les propriétés de l'équation différentielle.

### 2. Stabilité numérique

Même si la dynamique est raisonnable, le solveur peut être instable selon le pas, la méthode et les tolérances.

Une simulation Euler avec un pas trop grand peut produire des résultats mauvais même pour une équation simple.

### 3. Stabilité de l'entraînement

Le modèle peut être difficile à entraîner :

- gradients instables ;
- NFE élevé ;
- loss qui oscille ;
- sensibilité aux seeds ;
- dépendance forte aux hyperparamètres.

### 4. Stabilité en inférence

Un modèle peut bien s'entraîner, mais devenir fragile en production face à :

- données bruitées ;
- délais inattendus ;
- valeurs manquantes ;
- séquences plus longues ;
- distribution différente.

### 5. Stabilité système

Dans une architecture complète, stabilité peut aussi signifier : latence prévisible, coût borné, logs exploitables, comportement de fallback.

## Points importants

- Stabilité mathématique, numérique et d'entraînement sont différentes.
- La stabilité en inférence doit être testée.
- La stabilité système inclut coût et latence.
- Dire "le modèle est stable" ne suffit pas.
- Il faut préciser la métrique et le protocole.

## Prolongement

Un rapport sérieux devrait écrire : "stable selon telle métrique, sur tel scénario, avec tel solveur". C'est moins vendeur, mais beaucoup plus utile.
