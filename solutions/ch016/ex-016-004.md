# EX-016-004 - Comparaison expérimentale

## Énoncé

Proposez un protocole minimal pour vérifier qu'un LTC apporte quelque chose par rapport à un GRU.

## Ce que l'exercice vérifie

L'exercice vérifie la rigueur expérimentale. Un LTC doit battre une baseline GRU sérieuse sur des critères définis, pas seulement paraître plus sophistiqué.

## Solution détaillée

### Dataset et splits

Utiliser le même dataset, les mêmes splits train/validation/test et la même politique de normalisation.

Si les données sont temporelles, le split doit respecter l'ordre temporel.

### Baselines

Comparer au minimum :

```text
GRU
GRU + Delta t
LTC
```

Le GRU + `Delta t` est important, car il teste une solution simple qui traite déjà le délai.

### Budget comparable

Documenter :

- nombre de paramètres ;
- budget d'entraînement ;
- learning rate search ;
- batch size ;
- nombre d'epochs ;
- matériel.

### Métriques

Mesurer :

- qualité principale ;
- latence ;
- mémoire ;
- coût d'entraînement ;
- NFE ou coût de solveur ;
- stabilité entre seeds ;
- robustesse aux délais et valeurs manquantes.

### Tests de robustesse

Ajouter des perturbations :

- délais modifiés ;
- bruit ;
- trous dans les observations ;
- séquences plus longues ;
- changement de régime.

## Points importants

- Comparer avec GRU + `Delta t`, pas seulement GRU naïf.
- Documenter le coût du solveur.
- Mesurer qualité et coût.
- Tester plusieurs seeds si possible.
- Vérifier les scénarios irréguliers où le LTC est censé aider.

## Prolongement

Une conclusion utile pourrait être : "le LTC améliore la robustesse aux délais irréguliers, mais coûte plus cher". Le choix dépend alors du contexte d'application.
