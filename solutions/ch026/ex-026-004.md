# EX-026-004 - Tableau de bord Switch

## Énoncé

Concevez un tableau de bord minimal pour surveiller l'entraînement d'une couche Switch.

## Ce que l'exercice vérifie

L'exercice vérifie l'observabilité nécessaire au routage top-1. Switch simplifie le routage, mais ne supprime pas les risques.

## Solution détaillée

Métriques minimales :

| Métrique | Rôle |
|---|---|
| Tokens par expert | Voir la charge |
| Taux de tokens débordés | Mesurer l'effet de la capacité |
| Loss auxiliaire | Suivre l'équilibrage |
| Entropie du routeur | Diagnostiquer collapse ou uniformité excessive |
| Latence de dispatch | Mesurer overhead |
| Utilisation mémoire | Suivre pression matérielle |
| Qualité validation | Vérifier que le routage aide la tâche |
| Experts morts | Identifier experts presque jamais utilisés |

Vues utiles :

- par couche ;
- par batch ;
- par période d'entraînement ;
- par sous-domaine de données ;
- par device si distribué.

Alertes :

- taux de débordement élevé ;
- un expert reçoit trop de tokens ;
- un expert reçoit presque zéro token ;
- loss auxiliaire divergente ;
- latence p95 instable.

## Points importants

- Switch a besoin de monitoring malgré sa simplicité.
- Le top-1 peut créer des hot spots.
- Les tokens débordés sont critiques.
- La qualité de validation doit être lue avec les métriques de routage.
- Les vues par couche évitent de cacher les problèmes.

## Prolongement

Un tableau de bord utile doit permettre de répondre vite : le problème vient-il du modèle, du routeur, de la capacité ou du matériel ?
