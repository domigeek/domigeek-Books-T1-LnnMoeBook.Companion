# EX-026-003 - Capacité et débordement

## Énoncé

Pour `T = 1024` tokens, `N = 16` experts et un facteur de capacité de `1.25`, calculez la capacité par expert. Simulez ensuite une distribution déséquilibrée et comptez les tokens débordés.

## Ce que l'exercice vérifie

L'exercice vérifie le calcul de capacité dans un MoE top-1 et l'impact du déséquilibre.

## Solution détaillée

Capacité moyenne par expert sans facteur :

```text
T / N = 1024 / 16 = 64
```

Avec facteur de capacité `1.25` :

```text
capacité = 64 * 1.25 = 80
```

Chaque expert peut donc accepter environ :

```text
80 tokens
```

Supposons une distribution déséquilibrée :

```text
expert 0 : 150 tokens
expert 1 : 90 tokens
expert 2 : 70 tokens
autres experts : charge <= 80
```

Tokens débordés :

```text
expert 0 : 150 - 80 = 70
expert 1 : 90 - 80 = 10
expert 2 : 0
```

Total débordé dans cet exemple :

```text
80 tokens
```

Le facteur de capacité ajoute de la marge, mais pas une garantie. Si le routeur concentre trop de tokens, certains seront rejetés, reroutés ou traités en fallback selon l'implémentation.

## Points importants

- Charge moyenne : `64`.
- Capacité avec facteur `1.25` : `80`.
- Le déséquilibre crée des tokens débordés.
- Plus de capacité réduit le débordement mais augmente le coût.
- Le meilleur remède reste un routage mieux équilibré.

## Prolongement

Un dashboard Switch doit suivre le taux de débordement par expert, pas seulement la moyenne globale.
