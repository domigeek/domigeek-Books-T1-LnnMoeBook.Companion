# EX-026-005 - Le top-1 n'est pas toujours meilleur

## Énoncé

Expliquez un scénario où le routage top-k pourrait être préférable au routage Switch top-1.

## Ce que l'exercice vérifie

L'exercice vérifie la nuance. Switch top-1 simplifie beaucoup, mais la simplicité n'est pas toujours le meilleur compromis.

## Solution détaillée

Un routage top-k peut être préférable si la tâche bénéficie de contributions complémentaires.

Exemple : génération de code dans un contexte multilingue avec explication.

Un token ou une représentation peut relever à la fois :

- de la syntaxe du langage ;
- du style documentaire ;
- d'un raisonnement algorithmique ;
- d'un contexte naturel en français.

Avec top-1, un seul expert traite le token. Si le routeur choisit mal, il n'y a pas de deuxième contribution.

Avec top-2, deux experts peuvent contribuer. Cela peut rendre le modèle plus robuste dans les cas ambigus.

Mais le coût augmente :

- deux appels experts ;
- recombinaison ;
- plus de communication ;
- plus de mémoire active ;
- latence potentiellement supérieure.

Donc top-k est préférable seulement si le gain de qualité ou robustesse justifie le coût.

## Points importants

- Top-1 réduit le coût et la complexité.
- Top-k permet une coopération d'experts.
- Top-k peut aider les cas ambigus.
- Le coût actif augmente.
- Le choix doit être mesuré par tâche et infrastructure.

## Prolongement

La bonne conclusion n'est pas "top-k est meilleur", mais "top-k peut être rentable quand la complémentarité d'experts améliore assez la qualité".
