# EX-026-001 - Routeur Switch top-1

## Énoncé

Écrivez un routeur qui reçoit une matrice de logits `tokens x experts`, applique une softmax, sélectionne l'expert maximal pour chaque token et retourne la distribution de charge par expert.

## Ce que l'exercice vérifie

L'exercice vérifie le mécanisme minimal de Switch : un token, un expert.

## Solution détaillée

Pseudo-code :

```text
input logits[T, E]
probabilities = softmax(logits, axis=experts)
selectedExpert[t] = argmax(probabilities[t, :])
load[e] = count(selectedExpert == e)
return selectedExpert, probabilities, load
```

Exemple :

```text
logits =
token 0 : [3.0, 1.0, 0.0]
token 1 : [0.1, 2.0, 1.0]
token 2 : [0.2, 0.4, 5.0]
token 3 : [4.0, 3.0, 0.0]
```

Experts sélectionnés :

```text
token 0 -> expert 0
token 1 -> expert 1
token 2 -> expert 2
token 3 -> expert 0
```

Charge :

```text
expert 0 : 2
expert 1 : 1
expert 2 : 1
```

Tests à écrire :

- un seul expert par token ;
- indices dans `[0, E-1]` ;
- somme des charges = nombre de tokens ;
- comportement déterministe sur logits fixes ;
- cas d'égalité défini ou documenté.

## Points importants

- Switch sélectionne top-1.
- Le softmax donne les probabilités du routeur.
- L'argmax choisit l'expert actif.
- La charge par expert est indispensable au monitoring.
- Les égalités doivent être gérées explicitement.

## Prolongement

Dans une vraie couche Switch, il faut aussi gérer capacité par expert, tokens débordés, loss auxiliaire et dispatch.
