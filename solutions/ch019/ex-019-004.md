# EX-019-004 - Mémoire et LFM

## Énoncé

Pourquoi un LFM, même avec contexte long, ne remplace-t-il pas une mémoire persistante gouvernée ?

## Ce que l'exercice vérifie

L'exercice vérifie la distinction entre contexte long et mémoire gouvernée. Avoir plus de tokens disponibles ne donne pas automatiquement une mémoire fiable.

## Solution détaillée

Un contexte long est une entrée temporaire. Le modèle peut lire davantage d'information dans l'appel courant.

Une mémoire persistante gouvernée doit gérer :

- écriture ;
- correction ;
- suppression ;
- oubli contrôlé ;
- provenance ;
- versionnement ;
- permissions ;
- audit ;
- durée de vie ;
- politiques de confidentialité.

Même si un LFM accepte un long contexte, ce contexte ne dit pas :

- quelles informations doivent être conservées après l'appel ;
- qui peut les lire ;
- quand les supprimer ;
- comment les corriger ;
- quelle source fait autorité ;
- quelle version était utilisée.

Le contexte long aide à traiter plus d'information à la fois. La mémoire gouvernée aide à gérer l'information dans le temps et dans l'organisation.

## Points importants

- Contexte long n'est pas mémoire persistante.
- La mémoire demande gouvernance et audit.
- Les permissions doivent être explicites.
- La provenance et le versionnement comptent.
- Un LFM peut utiliser une mémoire externe, mais ne la remplace pas.

## Prolongement

Dans une architecture documentaire ou agentique, le modèle lit un contexte. Le système décide ce qui est écrit, oublié, corrigé et autorisé.
