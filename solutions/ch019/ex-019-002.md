# EX-019-002 - Lire un claim LFM

## Énoncé

Prenez une affirmation du type « ce modèle est plus rapide que tel modèle concurrent ». Quelles informations faut-il demander avant de la considérer sérieusement ?

## Ce que l'exercice vérifie

L'exercice vérifie le réflexe d'audit des claims de performance. "Plus rapide" ne veut rien dire sans protocole.

## Solution détaillée

Il faut demander :

- matériel utilisé ;
- runtime et framework ;
- précision numérique ;
- quantification ;
- taille du modèle ;
- batch size ;
- longueur de contexte ;
- type de tâche ;
- métrique de latence ;
- débit ;
- mémoire ;
- qualité obtenue ;
- version exacte du modèle ;
- reproductibilité.

Une phrase comme :

```text
modèle A est 2x plus rapide que modèle B
```

peut changer complètement selon :

```text
CPU ou GPU
batch 1 ou batch 64
contexte 512 ou 32 000 tokens
FP16 ou INT4
runtime optimisé ou naïf
```

Il faut aussi regarder la qualité. Un modèle plus rapide mais beaucoup moins bon ne répond pas au même besoin.

La bonne lecture est :

```text
plus rapide dans quelles conditions, sur quelle tâche, avec quelle qualité ?
```

## Points importants

- "Plus rapide" exige un protocole.
- Le matériel et le runtime changent tout.
- La longueur de contexte influence fortement les résultats.
- La qualité associée doit être mesurée.
- La reproductibilité est essentielle.

## Prolongement

Pour un livre technique, il vaut mieux citer les claims comme des résultats rapportés dans un cadre donné, et éviter d'en faire des vérités générales.
