# EX-019-005 - Évaluer un modèle local

## Énoncé

Définissez un protocole minimal pour comparer un LFM compact et un Transformer compact dans une application locale.

## Ce que l'exercice vérifie

L'exercice vérifie une comparaison réaliste en environnement contraint. Sur machine locale, qualité, latence, mémoire et énergie comptent autant que l'architecture.

## Solution détaillée

### Conditions fixes

Utiliser le même matériel :

```text
même CPU/GPU/NPU
même RAM
même OS
même runtime
```

Documenter aussi :

- précision numérique ;
- quantification ;
- taille des modèles ;
- version exacte ;
- longueur de contexte ;
- batch size.

### Tâche

Choisir une tâche locale précise :

```text
résumé de notes
classification de logs
assistant embarqué
réponse courte documentaire locale
```

Les deux modèles doivent recevoir les mêmes données et les mêmes prompts ou entrées.

### Métriques

Mesurer :

- qualité de tâche ;
- latence p50/p95 ;
- mémoire maximale ;
- débit ;
- coût énergétique si possible ;
- temps de chargement ;
- stabilité sur plusieurs runs ;
- erreurs qualitatives.

### Robustesse

Tester :

- entrées plus longues ;
- bruit ;
- données hors distribution ;
- contraintes mémoire ;
- mode offline complet.

### Analyse

Ne pas conclure seulement sur la moyenne. Un modèle local doit être prévisible. Une latence p95 trop haute peut ruiner l'expérience même si la moyenne est bonne.

## Points importants

- Même matériel, même runtime, même tâche.
- Documenter quantification et contexte.
- Mesurer qualité et coût système.
- Regarder p95, pas seulement moyenne.
- Tester robustesse et erreurs.

## Prolongement

Une conclusion utile pourrait être : "le LFM compact est plus rapide sur contexte long, mais le Transformer compact est meilleur sur réponses courtes". Ce type de résultat guide vraiment l'architecture.
