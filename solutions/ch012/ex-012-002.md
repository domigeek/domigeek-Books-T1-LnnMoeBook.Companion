# EX-012-002 - Attention ou état compact

## Énoncé

Pour chacun des cas suivants, dites si vous commenceriez plutôt par un Transformer, un SSM ou une architecture hybride : document juridique long, flux de capteurs industriels, conversation courte, audio long, logs applicatifs en streaming.

## Ce que l'exercice vérifie

L'exercice vérifie le choix d'architecture par contrainte. Il ne s'agit pas de voter pour une famille de modèles. Il faut regarder la nature des données, la longueur, le besoin de récupération exacte, la latence et le coût.

## Solution détaillée

### Document juridique long

Je commencerais par une architecture hybride :

```text
RAG + Transformer
```

Un document juridique demande souvent de retrouver des passages précis, citer des sources et comparer des clauses. L'attention est utile pour raisonner sur un contexte sélectionné, mais une fenêtre brute énorme n'est pas toujours le bon point de départ.

Baseline :

```text
recherche lexicale/vectorielle + réponse extractive simple
```

### Flux de capteurs industriels

Je commencerais plutôt par un SSM ou une architecture séquentielle compacte.

Les flux de capteurs sont longs, réguliers ou semi-réguliers, souvent orientés dynamique. Un état compact peut être plus adapté qu'une attention dense sur toute l'histoire.

Baseline :

```text
moyenne mobile, seuils, modèle AR simple, GRU
```

### Conversation courte

Je commencerais par un Transformer.

Pour une conversation courte, la fenêtre de contexte reste raisonnable. L'attention permet de relier les éléments récents et de gérer les références dans le dialogue.

Baseline :

```text
prompt simple sans mémoire externe
```

### Audio long

Je regarderais un SSM ou une architecture hybride.

L'audio long produit beaucoup de frames. Le coût de l'attention dense peut devenir lourd. Un modèle à état ou un découpage hiérarchique peut mieux gérer la longueur.

Baseline :

```text
fenêtrage + modèle local + agrégation
```

### Logs applicatifs en streaming

Je commencerais par SSM, GRU ou hybride avec mémoire d'événements.

Les logs arrivent en flux. On veut souvent suivre une dynamique, détecter une rupture et maintenir un état opérationnel. Une attention complète sur tout le passé serait coûteuse.

Baseline :

```text
règles, compteurs temporels, EWMA, détecteur statistique simple
```

## Points importants

- Les documents longs demandent souvent récupération et citation.
- Les flux longs favorisent souvent un état compact ou une approche streaming.
- Les conversations courtes sont un bon cas de Transformer classique.
- L'audio long impose des contraintes de longueur fortes.
- Les logs en streaming demandent état, observabilité et faible latence.

## Prolongement

Le bon choix initial n'est pas définitif. On commence avec une baseline simple, puis on ajoute de la complexité seulement si les métriques montrent que c'est nécessaire.
