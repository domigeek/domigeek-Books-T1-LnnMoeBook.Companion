# EX-012-004 - État latent et mémoire persistante

## Énoncé

Pourquoi un état SSM ne remplace-t-il pas une mémoire persistante gouvernée ?

## Ce que l'exercice vérifie

L'exercice vérifie la distinction entre état latent de modèle et mémoire persistante de système. Un SSM maintient un état pour traiter une séquence. Ce n'est pas une base de connaissances gouvernée.

## Solution détaillée

Un SSM maintient un état latent :

```text
s_t
```

Cet état résume l'information utile de la séquence selon la dynamique apprise. Il peut être très efficace pour traiter des flux longs.

Mais cet état est :

- compressé ;
- latent ;
- dépendant de la séquence courante ;
- difficile à inspecter ;
- non versionné ;
- non corrigeable directement ;
- non associé à des sources documentaires ;
- généralement non soumis à une politique de gouvernance explicite.

Une mémoire persistante gouvernée a d'autres responsabilités :

```text
stocker
versionner
auditer
supprimer
corriger
contrôler les accès
citer les sources
documenter les dates et provenances
```

Par exemple, si un profil utilisateur contient une préférence fausse, on doit pouvoir la corriger. Si une base documentaire contient un document expiré, on doit pouvoir l'invalider. Si une donnée personnelle doit être supprimée, il faut une procédure.

Un état SSM ne donne pas naturellement ces garanties. Il peut transporter un signal, mais pas servir de registre fiable.

## Points importants

- L'état SSM est utile pour la dynamique de séquence.
- Il n'est pas une mémoire documentaire.
- Il n'est pas directement auditable.
- Il ne fournit pas de gouvernance de données.
- Mémoire latente et mémoire persistante peuvent se compléter.

## Prolongement

Une architecture sérieuse peut utiliser un SSM pour suivre un flux et une mémoire externe pour conserver des faits. Le SSM aide à traiter le temps ; la mémoire gouvernée aide à gérer la responsabilité.
