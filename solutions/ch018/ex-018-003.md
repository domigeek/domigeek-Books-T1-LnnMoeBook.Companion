# EX-018-003 - OOD

## Énoncé

Pourquoi un bon score sur un dataset standard ne prouve-t-il pas une généralisation hors distribution ?

## Ce que l'exercice vérifie

L'exercice vérifie la différence entre performance sur un benchmark et robustesse hors distribution. Un test standard peut partager les mêmes biais que l'entraînement.

## Solution détaillée

Un dataset standard est souvent découpé en train, validation et test selon une procédure contrôlée. C'est utile, mais le test peut rester proche du train.

Exemples de biais partagés :

- mêmes capteurs ;
- mêmes périodes ;
- mêmes utilisateurs ;
- mêmes conditions météo ;
- mêmes classes dominantes ;
- mêmes artefacts de collecte ;
- mêmes règles de labellisation.

Un modèle peut apprendre ces régularités et obtenir un bon score. Cela ne prouve pas qu'il fonctionnera sur :

- un nouveau domaine ;
- un nouveau capteur ;
- une période future ;
- un bruit différent ;
- des événements rares ;
- des amplitudes jamais vues.

La généralisation hors distribution demande des tests explicitement séparés :

```text
train sur domaine A, test sur domaine B
train sur période 1, test sur période future
train sur conditions normales, test sur perturbations réalistes
```

Il faut aussi comparer avec des baselines. Si tous les modèles échouent hors distribution, le problème vient peut-être de la donnée, pas seulement de l'architecture.

## Points importants

- Le test standard peut être trop proche du train.
- Les biais de collecte peuvent être partagés.
- OOD signifie changement de distribution réel.
- Il faut construire des tests séparés par domaine, temps ou conditions.
- Un bon score benchmark n'est pas une preuve de robustesse générale.

## Prolongement

Pour les LNN, l'intérêt potentiel hors distribution doit être démontré par protocole : perturbations, domaines séparés, ablations et comparaison avec GRU, SSM, Transformer ou baselines simples.
